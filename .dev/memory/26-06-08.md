## 决策

1. **fallback 模型链调整**：所有 agent 和 category 的 `fallback_models` 链末尾从 `opencode-go/glm-5.1` 改为 `astroncodingplan/xopglm51`。
2. **#30 实施方案（v1）**：服务端 query 参数驱动，tab 用顶部 inline `<a>` 链接。
3. **#37 根因**：上层 slot 用了 `pointer-events-none` 防止空 slot 拦点击，但内层 toast 即便有 `pointer-events-auto`，在某些场景下 × 按钮的 click 仍被父级吞掉。修复：把 `pointer-events-auto` 和 `cursor-pointer` 直接钉在 × 按钮自身，不依赖继承。
4. **#38 实现方案（v1）**：新增 `/trade/lightning/{portfolio_id}/{asset}/execute` POST 路由，解析 entry.price_ref 到具体价格，调用 `broker.buy_amount(amount_wan*10000, price)`，返回 toast。
5. **#39 文案**：编辑弹窗顶部文案改为「请设置买入金额和价格以创建闪电单。保存后，在下单界面双击即可立即发出委托，适合提前埋伏多支个股，在接近触发条件时快速下单。」
6. **#40 价格选项**：`PRICE_REFERENCE_OPTIONS` 去掉 "close"，新增 `current_p1/p2/p3` 三个 key。
7. **#41 实施方案（v2 重做 #30）**：HTMX 局部刷新。`PositionsOrdersTabs` 容器加 `id="positions-orders-tab-panel"` 作为 swap 目标；每个 tab 链接加 `hx_get / hx_target / hx_swap / hx_push_url / hx_select`；同步把 `.dev/specs/09-backtest-report-tabs-and-logs.md` 第 3.1 节从「query 参数驱动的服务端切换」改为「HTMX 局部刷新 + query 参数同步 URL」。
8. **#38 followup 实施方案**：闪电单创建/更新时**预锁定价格**。新增 `TradeLightningEntry.cached_price` 字段；新增 `compute_cached_price(asset, price_ref)` 和 `last_closed_trade_date()` helper；`_lightning_row` 在 cached_price > 0 且非 current 时显示「label（price）」；execute 时非 current 一律用 `entry.cached_price` 下单（不重新解析实时价）。这是「看到的数 = 下单的数」契约。
