# 2026-05-31 对话记录

## 用户决策
- `millionaire` 与 `zillionaire` 被定义为同一个 `quantide` runtime 的两个 edition，而不是两个需要强隔离的独立 runtime。
- 不追求同机共存；一个用户只会选择 `millionaire` 或 `zillionaire` 其中一个。
- 后续讨论和实现中必须统一使用正确拼写：`millionaire`、`zillionaire`。

## 影响到的分析结论
- 之前关于“两个产品必须拆分顶层 import namespace、默认配置目录、运行目录”的硬性结论不再成立。
- `quantide` 可以继续作为共享技术标识与运行时身份存在。
- 后续需要重点解决的不是 runtime 隔离，而是 edition 识别、edition 级功能门控、edition 级文案/发布元数据管理，以及未来闭源增量代码如何叠加在共享 runtime 之上。

## 后续最小改动方向
- `AppState` 当前没有 edition 字段；运行时配置 `Settings` 也没有 edition 视图，因此 edition 还不是一等公民。
- `InitWizardService.get_feature_status()` 当前只根据初始化完成、Tushare token 和 gateway 可用性判断 backtest/simulation/live_trading，不包含 edition 约束。
- Header 组件 `header_component()` 已支持注入 `brand` 参数，但 `MainLayout.render()` 仍把品牌写死为“匡醍量化”，说明品牌展示层已具备抽离条件。
- 最小必要改动应围绕：edition 字段、edition 配置来源、集中式 feature gate、品牌文案配置、分发脚本/文档安装语义、以及 edition 可观测性展开，而不是立刻重命名 `quantide` 技术标识。

## 本轮对话：实盘/仿真实时 K 线能力分析

### 用户输入
- 分析 quantIDE 在配置 full-functional qmt gateway 后，实盘和仿真运行的策略是否能在盘中通过 `BarsFeed.get_bars` 等接口获得包含当日实盘价格的日线、分钟线和 30 分钟线。
- 如不能，提出符合现有技术栈的实施方案；必要时可 ssh 到 qmt 机器读取 `qmt-gateway` 源码。

### 助手输出
- 已确认 qmt-gateway 的 `QuoteService` 会通过 `/ws/quotes` 发布包含 `1m`、`30m`、`1d` 的行情 payload。
- 已确认 quantIDE 当前只把 gateway 行情用于最新价快照：`GatewayMarketDataAdapter` 消费 `1m` 生成 `QuoteSnapshot` 和 tick 事件，不缓存多周期 bar，也不暴露 `get_bars`。
- 已确认 `BarsFeedImpl` 当前仅正式支持日线，非日线会 warning 并降级；且它依赖 `LiveQuote`，没有接入 runtime 的 gateway market adapter。
- 已确认 live/paper 策略运行时每 2 秒调用 `market_data.snapshot()` 组装 quote 给 `on_bar`，没有将 `BarsFeed` 注入策略；`PaperBroker` 和 `GatewayBrokerWrapper` 的 `get_history` 也只支持 `1d`。
- 结论：当前不满足“通过 `BarsFeed.get_bars` 获得包含当日实时价格的日线、1 分钟线、30 分钟线”的需求；需要在 `MarketDataPort`/gateway adapter 中增加实时 bar 缓存，并让 `BarsFeedImpl` 和策略运行时消费这一路径。

## 本轮对话：实时日线 forming bar 需求拆分

### 用户输入
- 询问当前项目有多少个模块能返回行情数据或类似 `get_bars` 的接口，是否存在冗余。
- 要求澄清拟议 `BarDataPort` 与现有行情接口的关系，以及策略 `on_bar` 中最终应调用哪个接口。
- 明确 Millionaire v0.1 先不返回 `1m`、`30m` 数据，但必须返回实时日线 forming bar。
- 明确实时日线应由 tick 合成，不依赖 qmt 历史行情 API。
- 明确 `get_bars` 返回值取决于请求 `end` 与当前运行时钟的关系，且应返回当前 forming bar，而不是所谓已完成 bar。
- 要求在 GitHub 创建父 issue，并用子 issue 跟踪拆分需求。

### 助手输出
- 盘点出活跃生产模块中约 12 个行情相关入口，其中 `xtwrapper` 为退休 stub，不应作为有效数据源；主要冗余在历史 bar、实时 quote、broker history facade、strategy helper 的语义交叉。
- 调整设计建议：不再新增独立 `BarDataPort` 作为用户接口；应让 `BarsFeed` 成为策略 bar 数据的唯一语义入口，`MarketDataPort.snapshot` 仅保留为最新价/撮合/UI 快照接口。
- 明确 Millionaire v0.1 范围：只实现 realtime forming daily bar，不支持 `1m`/`30m` 返回。
