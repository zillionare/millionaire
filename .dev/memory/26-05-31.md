# 2026-05-31 对话记录

## 用户决策
- `millionaire` 与 `zillionaire` 被定义为同一个 `quantide` runtime 的两个 edition，而不是两个需要强隔离的独立 runtime。
- 不追求同机共存；一个用户只会选择 `millionaire` 或 `zillionaire` 其中一个。
- 后续讨论和实现中必须统一使用正确拼写：`millionaire`、`zillionaire`。

## 影响到的分析结论
- 之前关于“两个产品必须拆分顶层 import namespace、默认配置目录、运行目录”的硬性结论不再成立。
- `quantide` 可以继续作为共享技术标识与运行时身份存在。
- 后续需要重点解决的不是 runtime 隔离，而是 edition 识别、edition 级功能门控、edition 级文案/发布元数据管理，以及未来闭源增量代码如何叠加在共享 runtime 之上。

## 后续最小改动方向
- `AppState` 当前没有 edition 字段；运行时配置 `Settings` 也没有 edition 视图，因此 edition 还不是一等公民。
- `InitWizardService.get_feature_status()` 当前只根据初始化完成、Tushare token 和 gateway 可用性判断 backtest/simulation/live_trading，不包含 edition 约束。
- Header 组件 `header_component()` 已支持注入 `brand` 参数，但 `MainLayout.render()` 仍把品牌写死为“匡醍量化”，说明品牌展示层已具备抽离条件。
- 最小必要改动应围绕：edition 字段、edition 配置来源、集中式 feature gate、品牌文案配置、分发脚本/文档安装语义、以及 edition 可观测性展开，而不是立刻重命名 `quantide` 技术标识。
