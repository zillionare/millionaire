## 决策

- 4 个问题已与 Aaron 确认：
  1. 修复范围：所有 broker（sim / gateway / backtest）都需要支持。
  2. `end_dt` 语义：落在今日 → 包含今日 forming bar；落在过去 → 行为不变。
  3. data source：从 `LiveQuote` 拿今日 forming bar（含 OHLC 从首个 tick 起累积）。
  4. 暴露 `include_forming_bar: bool = True` 参数；False 时回退到 `previous_trade_date`。
- 跨日切换时 LiveQuote cache 必须重置（旧实例的 dict 已无意义）。
- 1d 的 `vol/amount` 是日内累积值，可以累加；1m 的 `vol/amount` 是单分钟切片，**不能**加到 daily 上。
- 形成 bar 的 `open` 锁在首个 tick 的 1d.open，不能被后续 tick 覆盖；`high/low` 取累计 max/min；`close` 取最新 tick 的 1m.close（fallback 1d.close）。
- TDD：先 10 条 failing tests 写出来 commit RED，再实现 GREEN。
- Backtest broker 没有 live tick，所以 `include_forming_bar` 接受为参数但 no-op，仅用于 API 对称。
- 抽象方法：把 `get_history` 加到 `Broker` 基类，三个实现签名对齐。

## 备注

- 关键陷阱：`LiveQuote._instance = None` **不能**清空 `live_quote` 这个模块级单例的内部 dict（`_quotes` / `_daily_bars` 等）。`live_quote` 是 `LiveQuote()` 在 import 时实例化并缓存到模块全局变量，所以测试 fixture 必须显式 `live_quote._daily_bars.clear()`。这个 bug 之前导致 `test_no_forming_bar_when_livequote_silent` 单独跑过、跟别的测试连跑就挂。
- `_concat_with_forming` 链路上踩过的坑：
  1. `live_quote.get_daily_bar` 返的 dict 里 `frame="1d"` 是 frame_type label 不是日期列，必须 drop。
  2. `dt` 字段要 rename 成 hist 的日期列名（`date` 或 `frame`）。
  3. `date` dtype 可能 μs vs ms 不一致，必须 cast。
  4. `unique(keep="last")` 之后**必须再 `sort("date")`**才能保证时间顺序。
- `LiveQuote._parse_ws_payload` 改了累计语义，但 `quote` 字段（`test_parse_gateway_ws_payload` 测的）仍保留单 tick 行为——只动了 daily_bar 累积部分。
- `_extract_forming_bar` 里的 `dt` 字段从 `datetime.date` 转成 `datetime.datetime` 时不要带时区，否则 polars 拼不上去。
- 测试用 `tests/assets/2024_bars.parquet`（TEST_ASSET=`688371.SH`, 2024-01-02 至 2024-12-31）避开 `DailyBarsStore` 真实数据库的复杂 setup。
- `Broker` 抽象方法不是 #20 的硬要求，但加上避免以后写自定义 broker 漏掉 `get_history`。
