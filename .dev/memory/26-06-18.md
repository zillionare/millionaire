## 给出的架构建议（要点）

核心矛盾：paper/live = "远程 gateway 行情 + 本地/远程撮合"，但测试不能连真 gateway、不能等真时间、不能 mock 框架。

### 思路：三个外部不可控源全部可控化
- **时间** ClockPort → `ReplayClock`（按数据时间轴快进，1 秒过完 1 个交易日）
- **行情** MarketDataPort → `ReplayMarketDataAdapter`（回放 tests/assets 固化的 tick/30m/日线）
- **交易** BrokerPort → `RecordingBroker`（独立规则撮合器，非框架的 PaperBroker）
- 关键：替换的是"被测系统的真实外部依赖"，不是 mock 框架内部，符合 test plan §1.1/§2.1 黑盒立场。

### 三档分层（不同真实度/代价）
1. **Deterministic Paper（秒级，主力）**：ReplayClock + ReplayMarket + RecordingBroker。覆盖几乎所有 paper AC（FR-013/125/360、AC-014-04/AC-020-07 模式无关性）。
2. **Gateway-Contract Paper（秒级）**：FakeQmtGateway 进程（fastapi+ws），实现 quantide↔gateway 协议，覆盖 FR-300/410~430/450 网关断开通知 + qtoid 贯通。
3. **Live-Path Smoke（真机 nightly）**：`@pytest.mark.requires_qmt`，只在 Windows+QMT 环境跑最小 1 笔冒烟，证明无 mock 路径真的通。

### 与 test plan 衔接
- 替换生产适配器（非 mock 内部）→ 不违反 §2.1
- 只通过新增公开入口 `bootstrap_with_adapters()` / `bootstrap_for_test()` 装配 → 不依赖私有 API（§2.1）
- RecordingBroker 与 ground truth 同住 tests/、独立实现、不 import quantide（§3）
- requires_qmt 的 skip 必须挂 GitHub issue（§1.3 第 2 条）

### 落地优先级
1. Phase 1：ReplayClock + ReplayMarketDataAdapter + RecordingBroker + bootstrap_for_test()，跑通双均线 paper 全生命周期对账 ground truth。
2. Phase 2：FakeQmtGateway 进程。
3. Phase 3：requires_qmt 冒烟 + nightly。

风控策略（FR-013/125/360）paper-only，天然只能落在第 1 档 → 证明第 1 档是必须项。
