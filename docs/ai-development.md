# 用 AI 辅助编写因子和策略

AI 可以帮助把公式、交易想法或券商接口转换成代码。框架提供统一数据、固定周期、策略模板与交易边界，让生成代码有明确约束；结果仍需要可复现的小样本验证。

## 把需求写成可检验的合同

向 AI 提供目标公式、输入字段及单位、周期、预热长度、何时可用、缺失值规则、证券池、信号和成交时序，以及几组手算输入输出。一次只增加一个因子或一项交易规则，先保留其他条件形成对照。

例如研究三日动量：

> 为 Millionaire 写一个日线因子，输入为按证券和交易日排序的原始日线及累计复权因子。输出后复权收盘价的三交易日收益，前 3 行为空。不得跨证券 shift，不得用未来回填。给出两只股票的小样本和预期值，再说明如何接入当前因子 catalog。复用已有 LightGBM 训练与调仓，不增加三重障碍，也不要把策略周期改成 30 分钟。

对应实际接入步骤见[因子与 LightGBM](factors-and-ml.md)。自定义策略可先使用[双均线子类示例](strategies.md)，避免让 AI 重新实现资金、持仓或券商连接。

## 本版可以怎样验证

1. 独立核对手算样本，检查日期排序、证券分组、空值与复权；不要只看 AI 自己生成的断言。
2. 检查计算只依赖决策时可得信息，固定策略周期和成交时序。
3. 用同一数据/费用运行基准，再只改变一个因子或参数做对照。
4. 检查成交、可用持仓、费用及失败日志，再转入仿真。
5. 保留源码、参数、输入数据与报告 ID；更改代码后重新生成实验。

## Web AI 因子工坊

不写代码的用户可以从 `/factors/studio` 开始：先选择“理解需求 → 生成因子代码 → 风洞体检 → 检验与查重结论”的会话流程，再让 Agent 只通过白名单工具写单个 `factor_dir/*.py` 文件、运行风洞、读取 IC 与正交性结果。工具写入被限制在 `factor_dir` 直接子级；风洞 `FAIL` 时不能生成统计结论，系统最多自动修复 3 轮，也可随时停止。通过后可以一键开启每日跟踪、加入策略预设做消融回测或进入因子详情页。AI 助手配置是可选项，跳过配置仍可使用 Demo、回测、因子研究和审计。

源码树提供离线审计入口，但它不是“任意策略自动审计器”。当前入口覆盖注册因子管线、未来数据扰动、随机/置换对照、人工 oracle、账户不变量和关键变异；具体命令与边界见[策略与因子审计](strategy-audit.md)。原生安装包是否包含同一入口，以 Release 产物和实际命令为准。

AI 生成代码后，至少要求它给出以下证据，而不是只给“已通过”：

1. 手算样本与独立断言，包含预热、空值、复权和缺失证券。
2. 未来扰动或截断对照，证明决策时刻之后的数据没有进入特征或信号。
3. 人工账户或独立实现的对拍结果，覆盖费用、T+1、拒单和重复提交。
4. 数据、源码、配置和报告指纹；修改后旧结论失效。
5. 失败时首个差异的日期、证券、输入、预期值和实际值。

运行成功、SHAP 面板可见或回测赚钱都不能替代正确性证据。审计不能证明任意代码毫无错误，也不能保证有利润；正确但没有预测能力的策略，应该能通过正确性检查，同时在收益评估中显示表现不佳。

## 官方因子研究 Skill 与 CLI 闭环

仓库在 `.github/skills/millionaire-factor-mining/SKILL.md`（并在
`skills/millionaire-factor-mining/SKILL.md` 提供同一技能包）给出面向 AI
Agent 的官方流程。Claude Code、GitHub Copilot 与 Cursor 可将该目录挂载为
项目技能/规则来源；它们通过 `millionaire` CLI 读取同一套服务函数，不复制
风洞或研究逻辑。

标准纪律是“生成单因子 → `factor check` 过风洞 → 查看正交性 → `factor study`
看 IC → 进入预设/消融回测”。`factor check --json` 使用稳定信封与退出码
（`0` 成功、`2` 参数/契约错误、`3` 风洞 `FAIL`、`4` 证据或数据不足）。
Agent 不得修改风洞阈值、种子、截断点或审计代码来绕过 `FAIL`；源码、配置或
数据指纹变化后，Web 徽章会降级为 `STALE`，必须重跑。研究 CLI 不启停仿真、
不改仿真持仓，也不提供实盘下单入口。
