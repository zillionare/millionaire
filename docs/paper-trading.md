# 仿真与持续运行

仿真使用当前行情和模拟账户运行策略，不会向券商发送真实订单。同一策略可从回测沿用，账户现金、持仓和活动委托由 Paper Broker 管理和持久化。

## 从回测转入

1. 完成一份无失败状态的回测，核对周期、参数、费用和数据前提。
2. 在对应记录选择“转仿真”，弹窗中输入“仿真本金”，再确认。
3. 确认页面显示“已转入仿真”，在“系统维护 → 运行时监控”查看策略、账户、周期和状态。
4. 在仿真交易页面查看资金、持仓、委托和成交；从“系统维护 → 账号管理”管理模拟账户。

转入时会保留回测策略配置；本金是新仿真账户的起点，不是把回测末期的持仓和收益复制为真实历史。CE 不提供“转实盘”；旧的实盘地址也不能启用真实交易。

## Shadow-Run

转入仿真后，框架默认建立双实例跟踪任务：仿真实例依据当前行情交易，回测影子实例按策略周期独立回放。日线策略在当天收盘、历史日线就绪后运行；30 分钟策略在 `10:00`、`10:30`、`11:00`、`11:30`、`13:30`、`14:00`、`14:30`、`15:00` 八个闭合槽位逐一运行。影子使用同一策略类和配置、历史数据以及回放时点有效的模型（若策略使用模型），在独立影子账户中重算，保存现金、持仓、成交及账户权益。仿真账户继续按实时行情运行。

在仿真账户的“对照”入口，或 `/tracking/<仿真账户ID>` 页面，查看影子与实际仿真账户的净值曲线、回撤、每日差额和逐 30m bar 明细。页面使用 `dry-run` 标识影子，支持开关；关闭影子不停止仿真。日线默认盘后任务时间为 18:45；30 分钟任务随闭合槽位推进，并在日终汇总。没有模型或数据、回放失败时会记为缺口，缺口不会提前消费后续 bar，而是在数据可用后的下一次运行时按时间顺序回补。标记为 `next_open` 的意图只在后续闭合槽位按下一 bar 开盘推进；重启后若某槽位已有持久 actual 事实或已完成信号，只恢复队列与状态。这里的“实际账户”指当前仿真账户，CE 不连接真实券商账户。

同一闭合 bar 的后续 tick 仍会独立推进 `next_open` 待执行队列，但不会重复触发策略回调。重启后若该槽位已有持久 actual 事实或已完成信号，只恢复队列与状态，不补写当前账户快照到过去槽位。

双实例对照支持日线的收盘与下一交易日开盘，以及 30 分钟闭合 bar 的收盘与下一根 bar 开盘成交时序。页面展示账户结果，结合订单与成交记录可进一步排查差异原因。自定义策略的额外状态和风控扩展是否完整复现需要单独验证；不能仅凭两条曲线就判定差异原因。

## 行情是必要前提

历史数据够用不代表实时行情已经配置。默认腾讯源关闭，需选择一次 30 天演示或接入[自己的行情扩展](quote-extensions.md)。检查最后行情时间、订阅证券和覆盖率。没有新行情、休市、预热不足或尚未到执行窗口时，策略可能保持运行但不发出订单。

日线 ML 策略通常在收盘前的窗口决策；不要用盘中几分钟没有订单判断它失效。30 分钟策略遵守自身周期。详细规则见[成交时序](execution.md)。

## 启停与恢复

只停某个策略，在“运行时监控”使用对应停止操作；停止策略不等于删除账户、卖出持仓或撤销全部订单。涉及委托时检查账户中的实际状态。

需要维护整个服务时使用控制器或服务命令。关闭前台窗口只关闭控制器，后台策略仍可运行。通过控制器停止服务后，持久化事实保留；启动时会恢复相关运行规格和账户，对处理中意图先对账，不能把未知提交直接重新当新单发送。

服务重启后检查运行状态、行情新鲜度、待处理意图及账户对账结果，再判断恢复是否正常。恢复机制不是对系统断电及所有未知故障都已验证的承诺，范围见[能力边界](scope.md)。

## 独立 HTTP 模拟柜台

普通仿真不要求另起 HTTP 柜台。需要验证 Broker 扩展和三模式接口时，使用[独立模拟柜台](simulated-counter.md)。它是可单独重启和对账的进程，不连接 QMT，也不会因启动该进程而让 CE 的实盘 UI 可用。
