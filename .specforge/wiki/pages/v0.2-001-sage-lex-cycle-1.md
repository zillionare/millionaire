## Issue 格式 (Sage 决策, 2026-06-17)

**Body** (自包含):
- `### 需求 ID` (FR-XXX)
- `### Spec 链接` (releases/v0.2/.specforge/project/.../spec-strategy.md#fr-XXX)
- **Spec 段落全文** (从 spec.md 复制, 不依赖外部文档)

**第一条 reply** (AC 列表):
- `## 验收标准 (AC 列表)` 标题
- 来源: acceptance.md FR-XXX 链接
- 完整 AC 列表, 带 `AC-1, AC-2, ...` 编号 (跟 acceptance.md AC-XXX-NN 一一对应)
- 使用规范说明: AC 必须独立验证通过才能 close issue

**理由** (来自用户):
- bug 报告时一目了然"本应该是什么, 错在哪, 怎么才算修复"
- 修复时逐条对照 AC
- 提交 commit 关联 issue, 实现可跟踪

## 流程工具使用经验

- `gh project item-add <number>`: number 不是 PVT ID
- `gh project item-add --owner <user>`: 默认 owner 是 viewer (quantclaws), 跨 user 项目需显式指定
- `gh project item-delete <number> --id <item_id>`: 需要 number + --id
- `gh issue edit --body`: 完整 body 替换, 不会保留原内容
