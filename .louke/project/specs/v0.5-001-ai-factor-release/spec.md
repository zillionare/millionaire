## 1. 目标与强约束边界

本规格将社区版（CE）发布前需补齐的“破圈亮点”与“实战完备性”固化为可执行工程契约。实施者必须严格遵守以下三条红线：

1. **清晰执行 CE 与 millionaire pro 产品边界（“官方不预置，扩展不封堵”）**：
   - **CE 官方发行版不预置提供以下已划归 millionaire pro 的现成内置模块**：① `daily_basic` 官方采集不扩充换手率（`turnover_rate`/`turnover_rate_f`）、估值（`pe_ttm`/`pb`）、量比等扩展字段落库；② 不内置正式行业分类（如申万行业）及一键行业/市值中性化组件；③ 内置 ML 示例不预置调仓持仓缓冲带（`hold_buffer`/`buffer_k`）与最小调仓阈值；④ 不提供真实交易通道及三重障碍、回撤卖出、成本止损等私有风险程序。
   - **保持开放扩展，严禁人为封堵用户或 AI 自研补齐**：框架的数据面板、外部因子插件（`factor_dir`）、用户策略目录（`strategy_dir`）与用户风控扩展接口必须保持开放通用——允许用户自己（或借助 AI）引入自定义扩展列（含换手率、估值、行业等）、编写带缓冲带的自定义调仓策略子类、编写自定义止盈止损风控或适配 HTTP 柜台；除维持既有 CE 实盘开关 `supports_live_trading()` 与默认空内置风控注册表外，严禁在代码中设置字段名黑名单或拦截用户自定义扩展。
   - **不实施已明确暂缓的外围项**：不做柜台 OpenAPI 规范生成与协议靶场 CLI；不做钉钉/邮件异常联动告警与 UI 测试入口；不引入商业签名证书构建强依赖。
2. **严守仓库目录与运行时路径纪律**：
   - 数据存储目录（`data_home`）、用户因子目录（`factor_dir`）、用户策略目录（`strategy_dir`）、因子预设、AI 会话记录、风洞证据快照、体验数据运行时副本一律通过 `quantide.config.paths` 与 `quantide.config.output_paths` 管理；持久化配置与默认用户工作目录存放在用户配置目录（`QUANTIDE_CONFIG_HOME`）或用户在向导中指定的外部绝对路径，严禁写入源码 checkout 内部（含软链别名），严禁绕过 `quantide.web.application` 产生根 `.sesskey`。
3. **严守代码质量门禁（`docs/quality.md`）**：
   - 新增与修改的生产代码必须满足认知复杂度 `CCR001 ≤ 15`、无超过 5 行重复代码 `R0801`（Web 内置 AI Agent 与 CLI 必须共享同一套底层服务函数）、单文件 `≤ 1000` 物理行、单函数 `≤ 50` 语句 / `≤ 15` 局部变量、Ruff `E501 ≤ 100`、单元测试覆盖率门禁及离线 socket 隔离要求，严禁通过 `noqa`、放宽阈值或删减既有门禁蒙混过关。

## 3. 功能需求（Functional Requirements）

### FR-5001：外部因子插件目录与声明式发现契约

系统必须支持在不修改包内 `quantide/factors/alpha.py` 的前提下，从持久化外部目录发现并加载用户/AI 编写的因子插件：

1. 用户因子目录（`factor_dir`）由初始化向导与系统设置统一持久化（见 `FR-5013`），未显式更改时默认为 `<app_config_dir>/factors/`（校验拒绝指向源码树内部路径）；原生包升级或卸载保留数据模式下该目录完整保留。
2. 每个单文件 `.py` 插件通过声明式结构暴露完整 `FactorDefinition` 元数据（`factor_id`、`display_name`、`group`、`bar_interval`、`required_columns`、`price_adjustment`、`warmup_bars`、`availability`、`direction`、`principle`、`formula`、`example`、`caveats`）与确定性计算函数 `compute(panel: pl.DataFrame) -> pl.Series | pl.DataFrame`。面板中若包含用户在自定义数据扩展中附加的额外列，只要满足 `required_columns` 声明即可正常传入计算，框架不做列名封锁。
3. 输入面板契约明确固定：按 `["asset", "date"]`（分钟级为 `["asset", "dt"]`）严格升序且键唯一；因子函数声明其期望输入是框架统一后复权价还是原始价，框架按声明供给并在开发校验中拦截二次重复复权。`hfq` 后 `adjust` 不再作为原始累计因子提供，插件在 `required_columns` 中声明 `adjust` 必须得到结构化契约诊断；`raw` 与用户扩展列保持开放。
4. 发现器采用容错枚举（不递归隐藏目录与 `__pycache__`）：遇到语法错误、导入异常、缺失必填元数据、非法 `factor_id`、与内置因子重名冲突或计算签名不符时，记录结构化 `SkippedFactorEntry`（文件路径、原因枚举、错误详情）并在因子页与 CLI 展示，严禁因单个坏插件导致服务启动崩溃或内置因子不可用。对于无法从可信源码重建、只能直接传入同一 `compute` 对象的程序化插件，风洞不得把冷/热两次调用冒充隔离证据，相关未来不变性检查必须为 `INCONCLUSIVE`。
5. 通过发现校验的外部因子与内置因子合并进入统一目录服务（保持稳定分组与排序），自动出现在 Web「因子」总览/侧栏/卡片/跟踪/自定义检验，以及兼容同周期的 LightGBM 策略因子选择列表中；源码内容哈希纳入 `factor_version`，文件修改后关联缓存、快照与模型特征指纹自动失效。

### FR-5002：单因子一键风洞校验管线

将 `quantide.audit` 的离线审计能力封装为面向内置因子与外部插件因子的标准准入风洞管线：

1. 校验管线至少串行或分组执行四项确定性检查：
   - **契约与边界检查**：输入缺失列、重复键、输出行数/键对齐、非有限值（`NaN`/`Inf` 区分合法空值 `null` 与非法浮点溢出）、预热窗口前 `warmup_bars` 行的空值行为。
   - **跨证券隔离检查**：打乱证券子集顺序或增删无关证券（不影响截面排名类因子声明除外；纯时序因子增删其他证券不得改变目标证券输出；截面因子明确声明 `scope="cross_sectional"`），检测未加 `.over("asset")` 的跨证券滚动/`shift` 串算。
   - **多截断点未来扰动检查**（继承 `v0.4-001 FR-4002`）：在至少 3 个覆盖预热后与除权/停牌边界的截断点 `t0`，将晚于 `t0` 可得时间的输入替换为合法零/哨兵值、极端合法值与固定种子随机值，要求 `≤ t0` 的输出逐位一致（含 `null` 掩码与 dtype）。
   - **插件自带手算小样本自检（可选但推荐）**：若插件提供 `GOLDEN_CASES` 小样本输入与期望输出，使用独立比较器逐行核对。
2. 输出遵循 `AuditReport` 版本化结构，绑定因子 `source_hash`、`data_hash` 与检查配置指纹，结论严格区分 `PASS`、`FAIL`、`INCONCLUSIVE`；全空输出或无未来行不得合成 `PASS`。
3. `FAIL` 时必须输出首次差异的时刻、证券代码、输入片段、期望值与实际值。未通过风洞（`FAIL`）的外部因子在 Web 因子列表与回测向导中显示醒目风险阻断标记，默认禁止勾选进入新建回测或启用后台自动跟踪（除非用户在开发调试模式下显式确认风险状态，且报告永久标记 `UNAUDITED_OR_FAILED`）。

### FR-5003：因子正交性与截面相关性诊断

为支持“每新增一个有效因子即可组合裂变出差异化策略”，避免 AI 批量堆砌同质冗余因子：

1. 在单因子检验（含自定义检验、自动跟踪快照及 CLI 因子检查）中，计算候选因子与当前已注册同周期因子集合在共同有效交易日上的截面 Spearman 秩相关系数序列及其日等权均值。
2. 报告输出按绝对平均截面秩相关降序排列的 Top-5 最相近已注册因子、`max_abs_rank_corr`、对应因子 ID 及共同有效交易日数。
3. 当 `max_abs_rank_corr` 超过版本化配置的共线性提示阈值（默认 `0.85`）时，在 UI 检验报告与 CLI JSON 中输出 `HIGH_COLLINEARITY` 诊断提示（非阻断错误，允许保留但明确提醒信息增量有限）；计算过程对单个对照因子缺失样本独立对齐，不因某一无关因子全空而污染其他相关性结果。

### FR-5004：因子组合预设（Factor Preset）与一键消融对比（Ablation）

将 LightGBM 策略的因子组合升级为一等公民配置对象：

1. 用户可通过 Web 界面或 CLI 创建、命名、列出、克隆和删除持久化的 **因子组合预设（Factor Preset）**，保存内容包括：预设 ID、显示名称、说明、绑定的目标策略类与固定 `bar_interval`、有序因子 ID 集合、训练标签类型（见 `FR-5010`）、以及策略核心超参（如 `top_k`、`train_window`、`future_return_horizon`、`retrain_days`、`fill_timing`、PIT 选池开关）。
2. 预设加载时校验所有引用因子均存在且周期匹配；若引用了已被删除或风洞 `FAIL` 的外部因子，明确报错阻断，严禁静默剔除缺失因子后以残缺子集继续运行。
3. 提供 **一键消融对比（Ablation Study）**：用户选定一个“基准预设（Baseline）”和一个或多个“对照预设（Variants，例如仅新增 1 个 AI 因子或替换标签类型）”，系统强制锁定同一回测起止区间、初始资金、费用模型、PIT 选池规则与随机种子，批量或队列执行回测。
4. 消融对比报告并排展示各预设的累计净值曲线、年化收益、相对基准超额、最大回撤、夏普/Calmar、双边换手率、总交易成本，以及差异因子在模型中的平均绝对 SHAP 贡献占比排名。

### FR-5005：免 Token 内置/一键离线体验数据包（Demo Bundle）

消除首次安装体验的数据源门槛：

1. 随安装包与源码树提供一份固定版本、经脱敏/合规构造且通过完整性校验的轻量离线体验数据包（Demo Bundle，压缩体积控制在合理安装包预算内，包含约 100～200 只覆盖主板/双创/ST 历史状态演变的代表性 A 股、至少 500 个连续交易日的权威交易日历、原始日线 OHLCV、累计复权因子、涨跌停限价及 `daily_basic` 的 `total_mv`/`circ_mv`）。
2. 初始化向导（Wizard）与系统数据源页面提供显式的 **“使用内置离线体验数据包”** 入口：无需填写 Tushare Token、无需联网请求外部接口，即可完成初始化并直接运行内置因子检验、风洞审计、LightGBM 回测、参数优化与单笔 SHAP 决策解释。
3. **严格物理隔离**：体验数据包解压/挂载在应用配置管辖的独立演示数据子目录，绝不写入或覆盖用户正式配置的 `data_home`；激活体验模式期间，界面全局顶栏常驻“体验数据模式（数据截至 YYYY-MM-DD，仅供功能体验）”横幅，并提供一键切换/配置正式数据源向导入口；体验模式下不启动外部历史增量爬取任务。

### FR-5006：面向 AI Agent 的官方 Skill 与结构化研究 CLI

兑现“面向 AI 和 A 股的开源量化框架”定位，让外部编程 Agent 可无界面闭环驱动因子研发：

1. 在 `millionaire` CLI 下新增结构化研究子命令族（全部支持 `--json` 输出标准 UTF-8 JSON，非有限浮点统一编码为 `null` 并附状态码，稳定语义退出码：`0` 成功/通过、`2` 参数或契约错误、`3` 风洞审计失败 `FAIL`、`4` 证据或数据不足 `INCONCLUSIVE`）：
   - `millionaire data status [--json]`：输出当前激活数据源模式（正式/体验）、数据覆盖起止日、可用数据集与字段 schema、缺口风险摘要（严禁输出任何未脱敏 Token）。
   - `millionaire factor list [--json]` / `millionaire factor init <factor_id> [--dir ...]`：列出已发现因子及跳过诊断；在用户因子目录生成带完整元数据注释与 `GOLDEN_CASES` 骨架的因子模板文件。
   - `millionaire factor check <path_or_id> [--json]`：对指定插件文件或因子 ID 执行 `FR-5002` 风洞校验 + 快速样本覆盖与 `FR-5003` 正交性检查，输出完整诊断与首次差异定位。
   - `millionaire factor study <factor_id> --start ... --end ... [--holdings 1,3,5] [--json]`：复用 `quantide.factors.research` 输出多持有期 Rank/Pearson IC、ICIR、十分位收益与 `as_of_date`。
   - `millionaire backtest run --strategy ... [--preset ... | --params ...] --start ... --end ... [--json]`：在隔离回测运行器中执行回测并输出报告 ID、核心绩效指标、费用汇总与 SHAP Top 贡献特征摘要。
2. 随仓库提供官方 Agent 技能包文档与提示契约（如 `.github/skills/millionaire-quant/SKILL.md` 或 `skills/millionaire-factor-mining/SKILL.md`，并在 `docs/ai-development.md` 说明如何在 Claude Code / GitHub Copilot / Cursor 中挂载），明确指导 Agent 遵守“生成单因子 → `factor check` 过风洞 → 查共线性 → `factor study` 看 IC → 建预设做消融回测”的纪律，严禁 Agent 修改审计阈值或绕过风洞报错。
3. 安全边界：所有 Agent 研究 CLI 命令仅读写外部因子目录、预设配置、研究快照与回测报告，默认不启停后台仿真进程、不修改仿真账户持仓，CE 中不存在任何实盘下单入口。

### FR-5007：Web UI 风洞体检卡片与指纹徽章可视化

将离线审计证据转化为用户与社区可直接感知的界面信任资产：

1. 在 Web「因子详情页」（共享状态条及检验报告页签）与「策略回测报告页」（报告头部及专门折叠面板）展示 **风洞体检徽章与详情卡片**。
2. 徽章状态由持久化的最新审计记录与当前实时计算的源码/配置/数据指纹比对动态得出，严格区分五种状态：
   - `PASS`（绿色：全部必需风洞项通过，且当前 `source_hash`、`config_hash`、`data_hash` 完全匹配）；
   - `FAIL`（红色：任一必需项失败，直接展示失败项名称与首次差异摘要）；
   - `INCONCLUSIVE`（琥珀色：样本或功效不足，无法下通过结论）；
   - `STALE`（灰色告警：存在历史审计记录，但因子/策略源码、配置或底层数据指纹已变化，旧结论已失效）；
   - `UNVERIFIED`（中性浅灰：尚未对该对象运行风洞体检，提供“立即运行风洞体检”后台任务按钮）。
3. 卡片内部分项展示检查维度（未来截断扰动、跨证券隔离、统计/随机对照、账户与撮合守恒不变量）、执行时间、运行 ID 与截断指纹，并提供导出 JSON/Markdown 证据入口。

### FR-5009：免积分历史日线数据源兜底与历史时点（PIT）股票池排雷

补齐个人用户无付费积分入门与 A 股截面防雷刚需（严格限定在 CE 边界内）：

1. **免积分历史日线适配器**：在现有 Tushare 日线与 BaoStock 分钟线基础上，补齐免积分历史日线获取能力（扩展 BaoStock 适配器支持日线 OHLCV、复权因子、交易日历、证券基础列表及历史交易/ST 状态字段，遵循 SQEP 字段/单位/时区规范并与 `v0.4-002` 数据源能力声明兼容）。无 Tushare Token 的用户可在向导中选择免积分历史源完成初始化与日常增量同步；若免积分源不提供 `total_mv`/`circ_mv` 市值列，依赖市值过滤的选项须明确提示能力不可用或降级为全市场流动性/成交额过滤，严禁伪造零市值。
2. **历史时点（Point-in-Time, PIT）股票池排雷规则**：为因子研究（`quantide.factors.research`）与日线截面策略选池提供统一、可配置、可审计的 `UniverseFilterConfig`，支持按信号日 `t0` 当时已知的历史事实独立开关过滤：
   - 剔除 `t0` 当日处于 ST / \*ST 或退市整理状态的证券（必须依据历史区间状态表或当日历史名称/状态快照判定，**严禁直接读取最新静态 `stock_list` 的当前股票名称来回溯过滤历史年份**；若当前数据源缺少历史日级 ST 记录，必须显式降级警告并在报告指纹中标记 `st_pit_unavailable`，不得静默假装已做 PIT 过滤）；
   - 剔除截至 `t0` 上市未满 `min_listing_days`（默认 60 个交易日，按 `list_date` 与交易日历计算）的新股及 `t0` 已退市证券；
   - 剔除 `t0` 当日停牌（成交量为 0 或停牌标记）的证券；
   - 在可执行选股阶段，按成交时序（`auction_close` 看 `t0` 收盘涨跌停状态、`next_open` 在下单执行层按 `t1` 开盘涨跌停规则撮合，选池阶段不得偷看 `t1` 行情！）处理涨跌停不可买入/不可卖出约束。
3. 每次研究与回测报告记录生效的 `UniverseFilterConfig` 及各规则排除的样本计数。**边界说明**：CE 官方内置采集不预置落库 `pe_ttm`/`pb`/`turnover_rate`，也不内置正式行业分类或一键行业市值中性化（上述内置能力归属 **millionaire pro**），但不得阻止用户在自定义面板或外部插件中自行引入并计算这些列。

### FR-5010：内置日线 ML 训练标签多样性

增强内置 LightGBM 流程在不同市场风格下的表达力（CE 官方内置示例保持 `top_k` 调仓而不预置 **millionaire pro** 的持仓缓冲带 `buffer_k`，但用户可在 `strategy_dir` 中通过自定义策略子类自行实现任意调仓缓冲逻辑）：

1. 为日线 ML 训练管线（`MLMomentumReversalStrategy` 及公共标签构造函数）新增可配置的 `label_kind` 参数，支持三种确定性标签：
   - `raw_return`（默认，保持向后兼容）：未来 `h` 个交易日复权收益；
   - `excess_mean`：未来 `h` 个交易日个股收益减去同信号日合格训练证券池的截面等权平均未来 `h` 日收益（截面去市场均值超额标签）；
   - `cs_rank`：同信号日合格训练证券池内未来 `h` 个交易日收益的截面百分位秩（归一化至 `[0.0, 1.0]` 或 `[-0.5, 0.5]`，并列值使用平均秩）。
2. **严格的截面与时间边界**：`excess_mean` 与 `cs_rank` 的截面均值/秩只能在同一个信号日 `t` 的合格候选池内部计算，严禁跨交易日池化排名；且整个交易日 `t` 的全部未来退出价格必须均早于或等于当前决策时刻 `t0` 的已成熟边界（与 `v0.4-001` 的标签成熟合同完全一致），任何未成熟交易日整日不得进入训练集。
3. `label_kind` 纳入模型存储键 `model_key`、回测参数快照、因子预设与 SHAP 预测解释上下文，保证重开历史报告解释时重建完全一致的目标模型。

### FR-5011：CE 教学级可启用开源风控扩展示例

在不破坏 CE“默认风险程序注册表为空、不内置私有风控”契约的前提下，让用户和 AI 拥有可运行的风控参考样板：

1. CE 启动时默认 `risk_program_registry` **继续保持为空**（保留既有全部单测与版本边界契约不变），且严禁包含任何三重障碍（triple-barrier）、移动回撤卖出、成本止损逻辑或历史私有 ID。
2. 新增与 `providers/extensions.py`（用户行情扩展）同构的 **用户风控扩展加载机制**：仅当用户在 `<app_config_dir>/extensions/` 下显式启用用户风控扩展（通过 CLI `millionaire risk-extension enable|disable|status` 或系统维护页开关）时，加载用户目录中的 `risk_extensions.py` 并注册其中的 `RiskProgramAdapter`。
3. 随 CE 提供一份可直接一键复制到 `<app_config_dir>/extensions/risk_extensions.py` 的 **50～80 行开源教学参考实现**：`example.single_asset_weight_cap`（单标的买入目标市值占账户总权益上限，默认 `max_weight=0.25`），同时实现回测 `overlay_factory` 与仿真 `live_strategy_factory`，并在文档中以此为例演示如何让 AI 编写并验证自定义风控叠加程序。

### FR-5013：初始化向导与系统设置统一管理三大目录及可选 AI 助手配置

面向不会编程的小白用户打通从首次安装到 AI 因子研发的配置闭环：

1. **运行环境步统一配置三大持久化工作目录**：在初始化向导“运行环境”步骤（及“系统维护 → 系统设置”）中，同时提供 **数据存储目录（`data_home`）**、**用户因子目录（`factor_dir`）**、**用户策略目录（`strategy_dir`）** 三个配置项。
2. **开箱即用默认路径与服务权限核验**：三个目录均预填对当前后台服务运行账户可写的持久化安全默认路径（`factor_dir` 默认为 `<app_config_dir>/factors`，`strategy_dir` 默认为 `<app_config_dir>/strategies`，在原生服务升级时完整保留），用户无需手敲任何路径即可直接下一步。提交保存时统一校验：① 严禁指向源码 checkout 内部（含符号链接解析后路径）；② 自动创建尚不存在的目录，并以当前服务进程身份执行真实创建/写入/删除探针校验，权限不足（如 Linux 系统服务账户无权访问个人主目录）时返回明确中文修复提示。保存后，`factor_dir` 与 `strategy_dir` 自动挂载至因子插件发现器与 `StrategyLoader`，无需用户再去策略页手工二次添加目录。
3. **可选（可跳过）的「AI 助手配置」向导步骤**：在初始化向导中新增类别为 `OPTIONAL`（允许一键跳过，不阻塞初始化完成）的 AI 模型配置步，并在“系统维护 → AI 助手”提供随时重配入口：
   - 支持常见 OpenAI 兼容服务商预设模板（如 DeepSeek、通义千问 DashScope、OpenAI、本地 Ollama、自定义 OpenAI 兼容端点），自动带出推荐 `base_url` 示例；
   - 配置字段包含 `provider_preset`、`base_url`、`api_key`、`model`、`timeout_seconds`（默认 `60`）与 `max_repair_rounds`（默认 `3`）；
   - 提供“测试连接”按钮，发送最小化连通性探测并明确区分鉴权失败（`401/403`）、模型名不存在（`404`）、限流（`429`）、端点不可达与响应格式不兼容；原始异常与前端状态严禁回显明文 `api_key`。

### FR-5014：Web 内置「AI 因子工坊」零代码会话闭环

允许不会编程的用户仅通过 Web 浏览器与内置 AI Agent 自然语言会话，一站式完成因子的编写、风洞排错、统计检验与组合回测：

1. **一级交互入口与未配置引导**：在顶部「因子」导航下提供显眼的 **「AI 写因子（AI 因子工坊）」** 页面/工作台（如 `/factors/studio`），并在因子总览与详情页提供快捷唤起入口。若用户初始化时跳过了 AI 助手配置，打开工坊时在面板内直接展示内嵌配置表单，保存连通后无缝开始对话。
2. **内置 OpenAI 兼容 Tool-Calling Agent 与底层服务复用**：后端实现基于标准 OpenAI 兼容协议（Chat Completions + Structured Tool Calling）的轻量受控 Agent 循环；所有工具动作直接调用与 `FR-5006` CLI 完全共享的 Python 服务层函数，严禁复制业务逻辑。
3. **严格白名单工具沙箱（仅限因子与预设范围）**：本版本 Web Agent 仅暴露以下 6 类受控领域工具，**严禁暴露任意 Shell/命令行执行或任意路径文件读写工具**：
   - `inspect_market_schema`：读取当前激活数据源（正式源或离线体验包）的可用字段、复权口径、周期与覆盖日期范围；
   - `search_registered_factors`：检索现有内置与外部因子的 ID、分组、原理与公式摘要；
   - `write_factor_plugin`：仅允许在规范化后的 `factor_dir` 单层目录下新建或更新 `<factor_id>.py`（强制校验文件名正则与真实父路径，拦截 `..` 路径穿越、软链逃逸及内置因子重名覆盖，且不触碰 `strategy_dir` 或安装目录）；
   - `run_factor_wind_tunnel`：在受控子进程中对该插件运行 `FR-5002` 四项确定性风洞校验与 `FR-5003` 正交性检查；
   - `run_factor_ic_study`：对已通过风洞校验的因子运行 `quantide.factors.research`，获取多持有期 RankIC、ICIR、十分位收益与 `as_of_date`；
   - `save_preset_and_run_ablation`：按用户指令或点击确认，将新因子并入指定基准因子集合保存为 `FactorPreset`，并触发 `FR-5004` 一键消融对比回测。
4. **风洞驱动的自动修复循环与有界预算**：当 `write_factor_plugin` 后的 `run_factor_wind_tunnel` 返回语法/契约错误或未来扰动/跨证券串算 `FAIL` 时，内置 Agent 自动读取结构化错误与 `first_difference` 进行代码修正并重新过风洞，**单次用户请求最多自动修复 `max_repair_rounds`（默认 3）轮**；严禁 Agent 修改风洞标准或静默跳过失败项；若达到上限仍未通过，保留草稿诊断并以通俗中文向用户说明卡点。
5. **面向小白的可视化进度流与持久化会话**：
   - 对话界面以实时进度卡片（HTMX 轮询或 SSE 流式状态）展示每一步状态：“理解需求 → 生成因子代码（默认折叠代码块，可展开）→ 风洞体检（含拦截与自动修复过程提示）→ 检验与查重结论卡片（RankIC、十分位柱状图、最高相关现有因子提示）”；
   - 风洞通过的结论卡片底部提供一键动作按钮：**“开启每日自动跟踪”**、**“加入策略预设做消融回测”**、**“查看因子详情页”**；
   - 会话列表、消息记录、工具调用摘要及产出的 `factor_id` / `run_id` 持久化在应用数据库中，刷新或重开浏览器不丢失，执行中支持随时点击“停止”取消当前轮次。

## 4. 非功能需求（Non-Functional Requirements）

- **NFR-5001（完全离线可验证）**：内置体验数据包、外部因子风洞校验、Web AI 因子工坊多轮工具调用与风洞自动修复闭环（通过注入确定性本地回环 Mock OpenAI 兼容服务端/传输层）、PIT 选池、截面标签、消融回测、30m Shadow-Run 与 BaoStock 日线解析契约测试全部可在 `--disable-socket --allow-unix-socket --allow-hosts=127.0.0.1,::1,localhost` 下离线运行通过，不依赖公网或真实大模型/数据源密钥。
- **NFR-5002（外部插件故障隔离与可控执行）**：外部因子枚举和计算失败不得影响主服务存活；单因子风洞检查、Web AI 工具调用中的因子计算与自定义检验均复用受控子进程 worker 与超时/内存预算，支持用户主动取消，避免死循环插件或慢模型响应卡死 Web 主进程。
- **NFR-5003（确定性与指纹可追溯）**：相同源码、数据、配置与随机种子下，外部因子计算、截面标签、消融对比及 30m 影子回放结果确定性可复现；任一输入指纹变动必须使风洞徽章与缓存失效。
- **NFR-5004（零仓库污染与升级持久性）**：所有运行期产物严格落在外部目录；执行测试、MkDocs 构建、Demo 数据加载、Web AI 会话写因子与 CLI 检查后，`python -m scripts.artifact_paths --check-layout` 与 `git status --short` 无任何运行时污染；原生安装包升级保留配置的 `factor_dir`、`strategy_dir`、`<app_config_dir>/presets/`、`<app_config_dir>/extensions/` 与 AI 助手配置。
- **NFR-5005（安装包体积预算）**：内置离线体验数据包采用列式高压缩 Parquet 存储，新增静态资源（Demo Bundle + README 图示）总增量控制在 `≤ 15 MB` 以内，不显著膨胀三平台原生安装包体积。
- **NFR-5006（质量与覆盖率门禁不退坡）**：全量遵守 `docs/quality.md` 的复杂度、重复度、行宽、文件大小与单元测试覆盖率要求；严禁删除或弱化既有 CE 实盘隔离测试与默认空风控注册表测试。
- **NFR-5007（大模型 API 凭证脱敏与沙箱边界安全）**：AI 助手的 `api_key` 在落盘时采用受限文件权限（`0600`）或配置库保护存储，API 响应、HTML 渲染、日志文件、审计报告与异常堆栈中一律脱敏（如仅显示末 4 位或掩码），绝不明文泄露；Web Agent 文件写入严格锁定在 `factor_dir` 单层 `.py` 文件内，单轮工具调用总步数设硬上限（默认 `≤ 12` 步）。

## 5. 推荐实施工作包与顺序（供实施 AI 分步推进）

为降低单次变更半径，建议实施 AI 按以下 8 个工作包顺序分批交付，每包独立通过单测与质量门禁：

1. **WP-1（统一目录与向导基础设施 + 因子插件底座 + 风洞与正交性服务）**：实现 `FR-5013`（运行环境三目录预填与权限校验部分）以及 `FR-5001`、`FR-5002`、`FR-5003` 的核心层与统一服务层，打通 `factor_dir` / `strategy_dir` 持久化挂载、外部因子容错发现、四项确定性风洞校验及截面秩相关计算。
2. **WP-2（AI 研究 CLI + 官方 Agent Skill + Web 风洞徽章）**：基于 WP-1 共享服务实现 `FR-5006`（数据/因子 CLI）、`FR-5007`（五态风洞徽章与详情卡片）与官方 `SKILL.md`。
3. **WP-3（PIT 股票池排雷 + 截面训练标签 + 因子预设与消融对比）**：实现 `FR-5009`（PIT 选池部分）、`FR-5010`、`FR-5004` 及 `millionaire preset / backtest run --json`，完成“多一个因子 → 多套预设策略消融对比”底层闭环。
4. **WP-4（可选 AI 助手配置 + Web「AI 因子工坊」零代码会话闭环）**：实现 `FR-5013`（向导可选 AI 配置步与设置页连通测试）与 `FR-5014`（OpenAI 兼容受控 Tool-Calling Agent、白名单工具沙箱、最多 3 轮风洞自动修复、可视化步骤卡片与一键转预设消融回测），用本地回环 Mock 大模型完成全链路离线验收。

## 2026-11-18 实施闭环补充

- **FR-5002 / FR-5007 证据身份**：持久风洞记录同时保存 `interval`、`price_adjustment` 与覆盖日线、分钟、日历、ST/证券/市值等依赖文件的数据签名。任一依赖修订后必须重新加载对应周期/复权口径的数据并重算徽章，不能因日线文件未变而沿用旧 `data_hash`。30 分钟同末日期修订必须使旧证据降级。
- **FR-5009 / FR-5010 标签与 PIT**：训练标签的退出日由权威交易日历精确推进；证券在退出日缺价时标签为缺失，不能顺延到下一存在行，也不能把停牌旧价当退出价。每个历史信号日按当日已知的可交易性与资格形成截面；`excess_mean`/`cs_rank` 在该日任一成员未成熟时整日排除。固定资产训练篮子可以保留，但篮子身份必须固定声明，且篮子内仍逐日执行资格规则。`raw_return` 继续表示信号日收盘到第 h 个交易日收盘的收益；因子研究 `next_open` 的 `t1 → t(h+1)` 是独立目标，不宣称两者完全同一。
- **FR-5012 Session 生命周期**：策略回调去重与 `next_open` 队列推进是独立生命周期。同一 completed bar 的后续 tick、跨午休/跨日但最新闭合仍同 bar、以及重启发现已完成信号时，队列仍推进；策略回调至多一次。已有 actual 事实的旧槽位不能被当前账户快照覆盖。
- **FR-5012 研究模型隔离**：研究、消融和解释产生的模型仅发布不可变实验引用，不移动 Paper/正式运行使用的 `latest` 指针。跨模式共享模型架构不等于共享可变 latest。
- **FR-5014 轮次身份**：AI 工坊维护独立于 `_ACTIVE` 的持久 generation。旧轮次在模型响应、自动 IC、工具卡片或最终状态提交前必须原子校验当前 generation；新轮次完成的清理不能使旧轮次重新获得写权限。
