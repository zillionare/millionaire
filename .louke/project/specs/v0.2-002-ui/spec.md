## 0. 范围与边界

### 0.1 在本 spec 范围内

- 任何在浏览器/Web 框架中**渲染**的内容 (账户视图、图表、表格、表单)
- 用户与系统的**交互流程** (点击、跳转、表单提交、参数编辑)
- 来自上游数据/事件的**展示、过滤、排序、刷新策略**
- 通知渠道的**配置界面** (事件触发本身在 001)
- 系统**配置向导** (init-wizard)
- UI 层的**响应性、可访问性、错误降级**

### 0.2 不在本 spec 范围内

- 业务计算规则 (策略评估指标、撮合、T+1 等) → v0.2-001-strategy-framework
- 数据来源与存储 (tushare / qmt-gateway) → v0.2-001-strategy-framework
- 调度路径与生命周期 → v0.2-001-strategy-framework FR-230/240/250
- SDK 元数据接口 → v0.2-001-strategy-framework FR-014/015

## 2. 功能需求

### 2.1 系统壳层与认证

> 对应 story §1 (1.1-1.4)。前版 spec.md 此章节由 §1.5 "导航与布局" 占位 (Maestro 擅自添加), 本稿删除 §1.5 并按 story §1 重写。

<a id="fr-0110"></a>
### FR-0110 启动路由分流

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ✅          |

系统根据自身状态路由首次访问请求：

- **刚装好** (未初始化): 用户被直接带入 init-wizard (§2.8 FR-0460)。Wizard 未走完前，其他任何页面都打不开。
- **已经配过** (已初始化): 用户进入登录页 (§2.1 FR-0120)。登录成功后进主界面。

<a id="fr-0120"></a>
### FR-0120 单用户登录与会话

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ✅          |

单用户系统：用户在登录页输入用户名和密码。登录成功后进入主界面。

- **不做账号注册**：本系统为单管理员系统，不提供注册流程。账号由 init-wizard (§2.8 FR-0460) 创建。
- **不做临时锁定**：连续 N 次密码错误不锁定账号。
- **不做超时自动登出**：会话保持到用户主动登出。

+--------------------------------------------------------+

|              |                            |            |
|              |  用户名: [_______________] |            |
|              |                            |            |
|              |  密  码: [_______________] |            |
|              |                            |            |

```

- 居中卡片式布局, 卡片宽度 ~ 360px, 高度自适应
- 卡片顶部: 品牌名 + 副标题 (无 logo 图, 仅文字, 与 §3 NFR-0040 字体层级一致)
- 卡片中部: 用户名 + 密码两个输入框 (上下排列), 登录按钮 (主操作, 中性深色实心 + 白字, §3 NFR-0040 约束)
- 卡片外背景: 浅灰色 (与登录后主界面区分, 提示"未进入系统"状态)

> **Sage**: Q-A120-1 "不做临时锁定"是否需要保留失败次数的审计日志（用于安全追溯），还是不记录任何失败信息?
>> **Aaron**: 完全不需要。这是部署在内网的系统。

<a id="fr-0130"></a>
### FR-0130 登出与个人设置

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ✅          |

登录用户在右上角用户菜单可执行：

- **退出登录**: 清除会话, 回到登录页
- **修改密码**: 进入密码修改页, 需提供旧密码 + 输入两次新密码（两次相同即可，**不校验复杂度**；与 init-wizard 校验规则一致）

> **不做**:
> - 改昵称（系统默认用户名 `admin`，无用户注册系统，故不支持昵称）
> - "查看最近登录记录"
> - 密码强度校验（仅校验"两次输入一致"）

<a id="fr-0140"></a>
### FR-0140 未登录访问重定向

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ✅          |

任何需要登录才能看的页面被未登录用户访问时：

1. 自动重定向到登录页
2. 登录成功后跳回用户原本想去的页面 (deep link 保留)

<a id="fr-0150"></a>
### FR-0150 主界面布局

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ✅          |

登录后主界面由三部分组成（对齐 Aaron 在 story §1.3 描述 + IDE quote 的实际布局）：

- **顶部 (nav bar)**:
  - 左边：系统 Logo 和名称
  - 中间：导航菜单（概览 / 策略 / 数据管理 / 系统管理 / 交易 等）
  - 右边：告警中心入口（带未读数小红点）、用户菜单
- **左侧导航栏 (side)**: 顶部 nav bar 菜单的二级菜单，支持多级菜单，可折叠/展开，状态被记住（持久化到本地）
- **主内容区 (main)**: 当前所选页面的内容

+------+-----------------------------------------------------------+
```

- **顶栏 (nav bar)** (高度 ~ 56px, 深色背景 + 白字):
  - 左侧: 品牌名 `Millionaire`
  - 中间: 一级导航菜单 (概览 / 策略 / 数据管理 / 系统管理 / 交易 等)
  - 右侧: 告警图标 (带未读数小红点 `3`) + 用户头像 (含下拉菜单: 修改密码 / 退出登录)
- **侧边栏 (side bar)** (宽度可调, 默认 240px, 浅色背景):
  - 显示当前一级菜单的二级菜单 (多级菜单支持折叠/展开)
  - 底部: 折叠按钮 (`[<<]` 收起 / `[>>]` 展开), 状态持久化到 localStorage
- **主内容区 (main area)** (剩余宽度, 浅灰背景):
  - 当前路由对应的页面内容

<a id="fr-0160"></a>
### FR-0160 告警中心入口与列表

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ✅          |

告警中心 (聚合入口) 行为：

- **入口**: 顶部导航右侧告警图标 + 未读数小红点
- **来源**: 系统运行中所有需要用户关注的事件 (数据同步错误、网关断连、风控事件等)
- **列表字段**: 时间、来源、级别、摘要
- **操作**:
  - 标记已读
  - 批量确认
  - 点击单条 → 跳到告警来源详情页

+------------------------------------------------------------------+
| 级别: [全部▾]  来源: [全部▾]  时间: [近 7 天▾]    [批量确认]    |
+------------------------------------------------------------------+

### FR-0180 功能降级

系统存在两种模式的功能降级：

- A类： 永久降级。当用户没有配置交易网关时为永久降级，直到用户配置后立即自动解除。
- B类： 临时降级。当系统配置了交易网关，但偶发不可连接。

> 对 A 类降级，状态记录在数据库中；对 B 类降级，状态记录在内存中，并在连接状态变更时更新。

对于 A 类功能降级：
- 实盘、仿真界面从 header 部分的导航按钮起 disable, 后台拦截所有相关路由，返回503
- 策略转仿真、转实盘按钮 disable
- "启动回测" 按钮: 仍可用 (回测不依赖 gateway, 可用历史数据回放)
- 启动仿真 / 转入实盘 / 实盘补单 / 实盘撤单 等所有依赖 gateway 的入口: disable
- 在被禁止入口，通过 mouse hover tip 提示: 此功能因交易网关未配置而无法使用。
- 在A 类降级解除后，被禁止入口立即恢复。

对于 B 类功能降级：
- 通过 alert 中心可以看到当前状态 -- 交易网关未连接
- 与实盘、仿真相关的数据刷新暂不可用，数据不要求更新，但不能导致页面空白。

**A 类与 B 类转换规则** (Aaron Round 2 决策):
- A 类 (永久) 配置网关后**立即**变正常 (无需测试通过, 后续如测试失败则进入 B 类)
- B 类 (临时) **永不升级为 A 类** (Aaron: "没必要考虑此问题。即永不升级")
- B 类降级期间运行中的实盘策略行为 (订单暂存 / 自动 dry-run 等) **不属于 UI 职责**, 由后台异常处理流程决定

**降级状态 UI 表现**

- 顶栏 "交易" 菜单按钮: 灰色, 鼠标 cursor: not-allowed
- hover 时显示 tooltip: "此功能因交易网关未配置而无法使用"
- 用户直接访问 URL (例: `/trade/live`): 后台拦截, 返回 503 + 提示页
- 顶栏 "策略" 下的 "启动回测" 按钮: 仍可用 (回测不依赖 gateway, 可用历史数据回放, 不需要提示"交易网关未配置")
- "启动仿真" / "转入实盘" / "实盘补单" / "实盘撤单" 等所有依赖 gateway 的入口: disable (与实盘一致, 仿真也依赖 gateway)

B 类降级 (有网关但偶发不可连接, 临时):

```
+------------------------------------------------------------------+
| [brand] Millionaire | 概览 / 策略 / 数据 / 系统 / 交易 |🔔|👤|
+------------------------------------------------------------------+
| ⚠ 交易网关连接断开, 数据可能不刷新。 [告警中心]   [✕]            |  ← 顶部 banner
+------+-----------------------------------------------------------+
| side |                                                           |
| bar  |                  main area                                |
| item |   (页面正常显示, 数据可能 stale, 但不空白)               |
+------+-----------------------------------------------------------+
```

- 顶栏正下方: 黄色 banner (警告色背景, 非红色背景, §3 NFR-0040 约束), banner 内含红色 ⚠ 图标 + 红色文字 "交易网关连接断开, 数据可能不刷新" (Round 10c: banner 背景黄色, 文字+图标用红色, 不大面积红色)
  > **(Round 10c 已统一)**: banner 颜色与 §3 NFR-0030 "实盘策略详情页横幅" 语义已统一 -- banner 背景用黄色 (warning), banner 内部文字/图标用红色 (error 强调), 满足 NFR-0040 "禁止大面积红色背景" 约束.
- banner 右侧: "告警中心" 链接 (跳转 §2.1 FR-0160) + 关闭按钮 (用户可手动关闭, 但下次连接断开仍会重新出现)
- 主内容区: 页面布局不变, 已有数据继续展示, 数据不要求实时刷新 (但页面不空白, §2.6 NFR-0030 错误降级约束)

**A 类降级时仍可用的入口**:

- 网关管理 (§2.6 FR-0340): 仍可用 (用来配置 gateway, 配置后立即解除 A 类降级)
- 启动回测: 仍可用 (回测不依赖 gateway)

#### 运行时实例生命周期 (Round 11 加)

运行时实例的状态机 (paper / live 都适用):

| 状态 | 含义 | 转换 |
|---|---|---|
| `idle` | 已创建, 未启动 | -> `running` (启动) |
| `running` | 正在运行 | -> `paused` (暂停, 仅实盘 dry-run) / `stopped` (停止) |
| `paused` | 暂停 (实盘 dry-run) | -> `running` (退出 dry-run) / `stopped` (停止) |
| `stopped` | 已停止, 不可重启 | (终态) |

**控制操作**:
- **启动**: idle -> running
- **暂停** (仅实盘): running -> paused (新订单不发出, 已发订单仍会成交)
- **退出 dry-run**: paused -> running (恢复下单)
- **停止**: running/paused -> stopped (终态, **不可重启**, 需以全新实例再次运行 - story §3.3 Aaron 注)

> - **第 1 层 (服务端持久化)** `account.hidden` 数据库字段: 记录"该账户已被隐藏"事实, 跨设备/跨浏览器一致; 换浏览器/清 localStorage 后隐藏仍然生效。上游契约见 [001-FR-220](../v0.2-001-strategy-framework/spec-trading.md)。

  - 账户无未结算持仓 (持仓为 0 或已全部清算)

  - 被隐藏账户**不参与**各类合计统计 (FR-0201 概览 总资产 / 可用现金 / 持仓市值 / 账户盈亏 合计; FR-0390 表格合计行)

  - 选中 -> "取消隐藏" 按钮 -> 服务端写入 `account.hidden = false` -> 该账户重新可见并参与合计
- **持久化分层**:
  - `account.hidden` (服务端字段) - 决定账户是否真的被隐藏, 跨设备一致
  - `display_hidden_accounts` (localStorage) - 仅决定 UI 是否展示已隐藏账户, 单浏览器偏好

### NFR-0040 视觉与组件规范

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ✅          |

> **本 FR 来源**: Aaron IDE quote (迁移记录之后追加: "非功能需求中, 应该定义界面的样式风格") + Aaron Round 2 决策 "按钮强调时, 文字使用红色这是我的决定, 红色是这个系统的主题色 — 但是, 因为这种颜色太抢眼, 所以不能大面积使用"。

为保证全网页面呈现一致、符合语义、清爽的界面布局, 视觉与组件规范如下:

- **字体层级**:
  - 页面标题: 24px / 粗体
  - 节标题: 18px / 中粗
  - 段落正文: 14px / 常规
  - 表格/列表: 13px / 常规
  - 辅助说明文字: 12px / 浅灰
- **图标风格**: 统一线性图标 (Linear Icons), 2px 描边, 与文字基线对齐
- **按钮风格** (Aaron Round 2 决策重写):
  - **主操作** (启动/确认): 实心背景 (**中性深色, 非红色**) + 白字 + 圆角 4px
  - **次操作** (取消/返回): 描边 + 文字色 + 圆角 4px
  - **危险操作** (删除/停止): **红色描边 + 红色文字** (不使用红色背景, 避免大面积红色)
  - **强调按钮文字**: 关键操作文字可用**红色** (Aaron 决策: 红色为系统主题色, 仅限文字/边框/图标)
  - **禁用**: 灰色, 鼠标 `cursor: not-allowed`
- **红色使用边界** (Aaron 决策, §1.4):
  - **允许**: 错误文字提示 / 状态徽章 / 危险操作描边 / 强调按钮文字 / 图标
  - **禁止**: 大面积背景 (按钮背景 / Modal 背景 / banner 背景 / toast 背景)
- **toast 红色** (§2.1 FR-0170 error 类型): **白底 + 红色边框 + 红色文字 + 红色 ✕ 图标** (非红底)
- **Modal 对话框**:
  - 居中浮层, 半透明遮罩
  - 标题 + 内容 + 主/次按钮 (右上角 × 关闭)
  - 危险操作要求二次确认 (输入名称)
- **语义色彩**:
  - 成功 (绿) / 错误 (红) / 警告 (黄) / 提示 (蓝) / 中性 (灰)
  - 每种语义色用于: 文字提示、状态徽章、按钮描边、toast 边框 (§2.1 FR-0170)
- **间距**: 8px 基准网格 (4 / 8 / 16 / 24 / 32)
- **圆角**: 按钮 4px, 卡片 8px, Modal 12px

**联动接口**:
- 上游: FastHTML + MonsterUI (项目 README 选型)

<a id="nfr-0050"></a>
### NFR-0050 局部刷新与失败隔离

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ✅          |

> **本 NFR 来源**: GPT-5.4 review §3.2 + Aaron Round 2 决策 Q2=A。

量化 UI 涉及资产/持仓/委托/告警/账户等多源数据, 任何单一数据源失败或局部刷新不得阻塞整页。具体约束:

- **失败隔离**: 单个数据区域 (例: 委托列表 / 账户信息 / 告警中心) 加载失败或刷新失败时, **不能**导致整页空白或报错。该失败区域独立展示"加载失败"占位与重试按钮, 其他区域保持正常。
- **不闪屏**: 局部刷新 (FastHTML `hx-swap` 等) 不得造成整页跳动或闪烁; 已渲染的内容不应被无谓重排。
- **占位重试**: 失败区域统一占位样式: 灰色背景 + 错误图标 + "加载失败"文字 + "重试"按钮; 点击重试后, 该区域独立重新加载, 不影响其他区域。

**参考实现**: `quantide/web/pages/trade_main.py` 的局部刷新与失败隔离模式。

**联动接口**:
- 上游: 所有 §2.x 含数据展示的 FR (例: §2.1 FR-0160 / §2.3 FR-0080 / §2.4 FR-0390/410/411 / §2.5 FR-0420/430 / §2.6 FR-0310)
- 下游: 单元测试 + e2e 测试 (模拟局部失败, 验证其他区域不受影响)

### NFR-0060 长任务交互

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ✅          |

> **本 NFR 来源**: GPT-5.4 review §3.3 + Aaron Round 2 决策 Q3=A。

主要场景: init-wizard 数据下载 (§2.8 FR-0460) / 数据同步任务 (§2.6 FR-0310) / 回测进度 (§2.3 FR-0080)。长任务在量化 UI 至关重要, 需统一交互约束:

- **进度展示最小粒度**: 任何长任务界面必须显示 (1) **百分比** 进度 (2) **当前步骤名** (例: "正在下载交易日历 (3/7)")。仅有 spinner 而无进度信息视为不达标。
