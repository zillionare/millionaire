- **Spec ID**: v0.2-002-ui
- **创建日期**: 2026-06-17
- **状态**: 草稿
- **上游 spec**:
  - [v0.2-001-strategy-framework](../v0.2-001-strategy-framework/spec.md) — 策略框架/调度/数据/SDK
- **本 spec 来源**: 从 v0.2-001-strategy-framework 抽取 UI 相关 FR,并补齐缺失

> **本 spec 仅定义 UI/交互层面的契约**。**计算规则、调度规则、数据契约、撮合规则等业务规则仍在 v0.2-001-strategy-framework**。本 spec 通过引用联动上游 FR,不重复定义。

## 0. 范围与边界

### 0.1 在本 spec 范围内

- 任何在浏览器/Web 框架中**渲染**的内容(账户视图、图表、表格、表单)
- 用户与系统的**交互流程**(点击、跳转、表单提交、参数编辑)
- 来自上游数据/事件的**展示、过滤、排序、刷新策略**
- 通知渠道的**配置界面**(事件触发本身在 001)
- 系统**配置向导**(init-wizard)
- UI 层的**响应性、可访问性、错误降级**

### 0.2 不在本 spec 范围内

- 业务计算规则(策略评估指标、撮合、T+1 等)→ v0.2-001-strategy-framework
- 数据来源与存储(tushare / qmt-gateway)→ v0.2-001-strategy-framework
- 调度路径与生命周期 → v0.2-001-strategy-framework FR-230/240/250
- SDK 元数据接口 → v0.2-001-strategy-framework FR-014/015

## 1. 用户故事

### UI-US-010
作为用户,我想在策略选择器中**看到所有可用的策略**,包括内置策略与用户策略,并能区分它们。

### UI-US-020
作为用户,我想**编辑策略参数**(覆盖 default_config 的默认值)再启动回测。

### UI-US-030
作为用户,我想在回测进行时**实时看到净值曲线推进**与进度条。

### UI-US-040
作为用户,我想切换到任意运行中策略,**查看其账户/委托/成交/指标**。

### UI-US-050
作为用户,我想在实盘/仿真界面**紧急手动下单**,且下单归属指定策略。

### UI-US-060
作为用户,我想将实盘策略**切换为 dry-run**,期间观察并行仿真的净值曲线以决定何时恢复。

### UI-US-070
作为用户,我想**通过二维码启用微信通知**,而非手工填 token。

### UI-US-080
作为首次安装者,我想通过**图形化向导**完成关键配置(密码/网关/通知/数据)。

### UI-US-090
作为用户,当数据完整性错误或下单失败时,我想在 UI 上**清晰看到问题与建议**,而非仅日志。

### UI-FR-010 策略发现与展示(含内置 vs 用户优先级)

| 有效需求 | 可测性 | 是否已决定 |
|---|---|---|
| ✅ | ✅ | ✅ |

UI 消费 [001-FR-020](../v0.2-001-strategy-framework/spec.md) 产出的策略元数据列表,按规则**展示、排序、过滤**。

#### 展示字段

每个策略在策略选择器中显示以下字段(均来自 001-FR-020 元数据 schema):

| 字段 | UI 展示 | 说明 |
|---|---|---|
| `name` | 主标题 | — |
| `description` | 副标题 | docstring 首行 |
| `strategy_type` | 类型徽章 | `day` / `live` / `risk` |
| `is_builtin` | 来源标签 | "内置" / "用户" |
| `default_config` | 参数摘要 | key=value 列表;空时显示"无参数" |
| `skipped_reasons` | 警告徽章 | 仅未识别类显示;悬浮显示详细原因 |

#### 内置 vs 用户策略的优先级与展示规则

| 场景 | 规则 |
|---|---|
| `strategy_id` 不冲突 | 内置与用户策略**都展示**,可分别选择运行 |
| `strategy_id` 冲突(用户策略同名) | UI 列表中**用户版本优先**;内置版本隐藏但可通过"显示被覆盖的内置策略"开关看到 |
| 排序 | 默认按 `is_builtin=False` 优先,然后按 `name` 字母升序 |
| 过滤 | 支持按 `strategy_type` 多选过滤、按 `is_builtin` 切换 |
| 搜索 | 按 `name` / `description` / `strategy_id` 模糊匹配 |

- 上游:[001-FR-020](../v0.2-001-strategy-framework/spec.md) — 提供元数据
- 下游:UI-FR-040(调度操作)按本 FR 的策略列表生成入口

### UI-FR-020 运行时参数编辑

| 有效需求 | 可测性 | 是否已决定 |
|---|---|---|
| ✅ | ✅ | ✅ |

用户在启动回测/仿真/实盘前,**编辑运行时参数**(本金/滑点/手续费),不被回测结果锁定。

> **运行时参数 ≠ 策略参数**:
> - **策略参数**:由 001-FR-010 `default_config()` 声明,跨模式自动带入(001-FR-030)
> - **运行时参数**:由 001-FR-200 定义,包括**本金、滑点、印花税比率、佣金比率、单笔最低佣金**——每次启动都允许独立设置,**不被回测锁定**

#### 字段

| 字段 | UI 控件 | 默认值 | 校验 |
|---|---|---|---|
| 本金 | 数字输入 | 上一次值 | `> 0` |
| 滑点(比率) | 百分比输入 | `0` | `0 ≤ x ≤ 0.1` |
| 印花税比率(卖方) | 百分比输入 | `0.001` | `0 ≤ x ≤ 0.01` |
| 佣金比率 | 百分比输入 | `0.0003` | `0 ≤ x ≤ 0.01` |
| 单笔最低佣金 | 数字输入 | `5` | `≥ 0` |

#### 持久化

- 用户最近一次值缓存在本地,**不写入回测结果**(被 001-FR-200 "不被回测结果锁定"约束)
- 切换运行模式(回测 → 仿真 → 实盘)时,UI 提供"沿用上次 / 重新设置"两选项;默认沿用上次

#### 联动接口

- 上游:[001-FR-200](../v0.2-001-strategy-framework/spec.md) — 参数定义
- 下游:UI-FR-040 — 启动按钮携带运行时参数

### UI-FR-040 调度操作界面

| 有效需求 | 可测性 | 是否已决定 |
|---|---|---|
| ✅ | ✅ | ✅ |

UI 提供启动/停止/切换模式的操作入口。**调度规则在 v0.2-001-strategy-framework FR-230/240/250 定义**,本 FR 仅定义 UI 操作。

#### 启动回测

- 入口:策略选择器(UI-FR-010)→ 选中策略 → "启动回测"
- 表单:策略参数(来自 `default_config`,可编辑)+ 运行时参数(UI-FR-020)+ 回测区间(起止日期)
- 提交后:进入回测进度视图(UI-FR-080)

#### 转入仿真 / 实盘

- 入口:已完成的回测结果 → "转仿真" / "转实盘"
- **仅日线策略**有此入口(001-FR-230);**实时策略**走 001-FR-240(无回测,直接进入仿真或实盘)
- 表单:运行时参数(允许覆盖) + 运行时模式
- 运行时参数允许与回测时不同(001-FR-200)

#### dry-run 切换

- 入口:实盘中策略的菜单 → "进入 dry-run"
- 见 UI-FR-060 完整定义

#### 停止

- 入口:任意运行中策略 → "停止"
- 立即生效;**已发订单不撤回**(001-FR-013 风控策略规则)

### UI-FR-060 dry-run 切换与并行仿真视图

| 有效需求 | 可测性 | 是否已决定 |
|---|---|---|
| ✅ | ✅ | ✅ |

#### 并行仿真视图

- UI 在该策略详情页提供**双 Y 轴净值曲线**:
  - 主轴:实盘 / dry-run 期间的真实净值
  - 副轴:并行仿真的模拟净值
- dry-run 期间的指标"参考并行仿真"(001-FR-440 原文)
