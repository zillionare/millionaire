## 0. 范围与边界

### 0.1 在本 spec 范围内

- 任何在浏览器/Web 框架中**渲染**的内容 (账户视图、图表、表格、表单)
- 用户与系统的**交互流程** (点击、跳转、表单提交、参数编辑)
- 来自上游数据/事件的**展示、过滤、排序、刷新策略**
- 通知渠道的**配置界面** (事件触发本身在 001)
- 系统**配置向导** (init-wizard)
- UI 层的**响应性、可访问性、错误降级**

### 0.2 不在本 spec 范围内

- 业务计算规则 (策略评估指标、撮合、T+1 等) → v0.2-001-strategy-framework
- 数据来源与存储 (tushare / qmt-gateway) → v0.2-001-strategy-framework
- 调度路径与生命周期 → v0.2-001-strategy-framework FR-230/240/250
- SDK 元数据接口 → v0.2-001-strategy-framework FR-014/015

## 2. 功能需求

### 2.1 系统壳层与认证

> 对应 story §1 (1.1-1.4)。前版 spec.md 此章节由 §1.5 "导航与布局" 占位 (Maestro 擅自添加), 本稿删除 §1.5 并按 story §1 重写。

#### UI-FR-A110 启动路由分流

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ⚠️          |

系统根据自身状态路由首次访问请求：

- **刚装好** (未初始化): 用户被直接带入 init-wizard (§2.8 UI-FR-460)。Wizard 未走完前，其他任何页面都打不开。
- **已经配过** (已初始化): 用户进入登录页 (§2.1 UI-FR-A120)。登录成功后进主界面。

#### UI-FR-A120 单用户登录与会话

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ⚠️          |

单用户系统：用户在登录页输入用户名和密码。登录成功后进入主界面。

- **不做账号注册**：本系统为单管理员系统，不提供注册流程。账号由 init-wizard (§2.8 UI-FR-460) 创建。
- **不做临时锁定**：连续 N 次密码错误不锁定账号。
- **不做超时自动登出**：会话保持到用户主动登出。

> **Sage:** Q-A120-1 "不做临时锁定"是否需要保留失败次数的审计日志（用于安全追溯），还是不记录任何失败信息?
> 状态: [open]

#### UI-FR-A130 登出与个人设置

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ⚠️          |

登录用户在右上角用户菜单可执行：

- **退出登录**: 清除会话, 回到登录页
- **个人设置**:
  - 改昵称 (自由文本)
  - 修改密码 (需要提供旧密码; 新密码强度校验)

> **Sage:** Q-A130 密码强度规则: 最低长度/复杂度要求是什么? 是否复用 init-wizard 的校验?
> 状态: [open]

> **不做**: 不提供"查看最近登录记录"功能。

#### UI-FR-A140 未登录访问重定向

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ⚠️          |

任何需要登录才能看的页面被未登录用户访问时：

1. 自动重定向到登录页
2. 登录成功后跳回用户原本想去的页面 (deep link 保留)

#### UI-FR-A150 主界面布局

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ⚠️          |

登录后主界面由三部分组成（对齐 Aaron 在 story §1.3 描述 + IDE quote 的实际布局）：

- **顶部 (nav bar)**:
  - 左边：系统 Logo 和名称
  - 中间：导航菜单（Dashboard / 策略 / 数据管理 / 系统管理 / 交易 等）
  - 右边：告警中心入口（带未读数小红点）、用户菜单
- **左侧导航栏 (side)**: 顶部 nav bar 菜单的二级菜单，支持多级菜单，可折叠/展开，状态被记住（持久化到本地）
- **主内容区 (main)**: 当前所选页面的内容

布局示意：

```
+------------------+-----------------------------------+
| brand            |   navigation  bar   | alert|avatar |
+-------------------------------------------------------+
|side |                                                 |
|     |             main area                           |
|bar  |                                                 |
+-------------------------------------------------------+
```

#### UI-FR-A160 告警中心入口与列表

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ⚠️          |

告警中心 (聚合入口) 行为：

- **入口**: 顶部导航右侧告警图标 + 未读数小红点
- **来源**: 系统运行中所有需要用户关注的事件 (数据同步错误、网关断连、风控事件等)
- **列表字段**: 时间、来源、级别、摘要
- **操作**:
  - 标记已读
  - 批量确认
  - 点击单条 → 跳到告警来源详情页

### 2.8 系统配置 (init-wizard)

> 对应 story §8 (8.1 首次安装 / 8.2 失败恢复 / 8.3 重新配置)

#### UI-FR-460 系统配置 init-wizard

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ⚠️          |

对应 story §8 主流程。基于图形化系统配置。首次启动时运行 init-wizard (通过 web) 引导用户配置关键项。

**首次安装流程** (story §8.1):

1. 欢迎页 → 选择"开始配置"
2. 运行环境: 监听地址、端口、URL 前缀、是否仅本机访问
3. 管理员账号: 用户名 + 密码
4. 数据目录
5. 数据源: 一个或多个网关 (qmt-gateway 等)
6. 首次下载范围: 交易日历起止、股票列表快照
7. 下载进度: 实时显示每个任务的进度, 可以选择跳过失败的
8. 通知渠道 (可后置)
9. 完成页

**失败恢复** (story §8.2):
- 任何一步失败时, 用户停留在该步骤, 看到错误详情和"重试"按钮
- 用户可重试, 也可选择"跳过该步骤"把它标记为待处理
- 已成功的步骤不会被回退; 重新进入 wizard 会从失败的那步继续
- 主界面顶部用横幅提醒用户还有"待处理"的 wizard 步骤

**重新配置** (story §8.3):
- 已初始化系统, 管理员可从"系统设置"再次进入 wizard 做"重新配置"
- **不允许**通过 wizard 改管理员密码
- **不允许**通过 wizard 改数据目录
- 其它项 (运行环境、网关、通知、首次下载) 都可再调一次
- 完成后回到主界面, 不重启进程

> **联动接口**:
> - 上游: init-wizard 是系统的初始化入口, 无上游
> - 下游: §2.1 UI-FR-A110 (启动路由分流) 根据 init-wizard 状态决定路由

> **Sage:** Q-460 wizard 跳过步骤: 跳过某步后, "待处理"状态如何呈现给用户? 顶部横幅的具体展示? 是否影响"已配置"判断 (例如, 跳过通知配置, 系统是否认为"已配置完成")?
> 状态: [open]
