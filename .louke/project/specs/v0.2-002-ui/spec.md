## 0. 范围与边界

### 0.1 在本 spec 范围内

- 任何在浏览器/Web 框架中**渲染**的内容 (账户视图、图表、表格、表单)
- 用户与系统的**交互流程** (点击、跳转、表单提交、参数编辑)
- 来自上游数据/事件的**展示、过滤、排序、刷新策略**
- 通知渠道的**配置界面** (事件触发本身在 001)
- 系统**配置向导** (init-wizard)
- UI 层的**响应性、可访问性、错误降级**

### 0.2 不在本 spec 范围内

- 业务计算规则 (策略评估指标、撮合、T+1 等) → v0.2-001-strategy-framework
- 数据来源与存储 (tushare / qmt-gateway) → v0.2-001-strategy-framework
- 调度路径与生命周期 → v0.2-001-strategy-framework FR-230/240/250
- SDK 元数据接口 → v0.2-001-strategy-framework FR-014/015

| 有效需求 | 可测性 | 是否已决定 |

#### UI-FR-A170 UI 内通知 (toast / banner)

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |

`story §7` 三层通知的第一层 ("UI 界面及时展示并自动消失的通知") 当前未沉淀为 FR。本 FR 补齐。

**通知类型** (按触发场景):

| 类型      | 触发场景                                            | 持续时间       | 用户操作        |
| --------- | --------------------------------------------------- | -------------- | --------------- |
| `success` | 操作成功 (例: 提交订单成功, 启用通知渠道成功)       | 3s 自动消失    | 鼠标 hover 暂停 |
| `error`   | 操作失败 (例: 下单失败, 网关断开)                   | **不自动消失** | 必须手动关闭    |
| `warning` | 需要提醒但不阻塞 (例: 跳过 wizard 步骤, 通知未配置) | 持续到用户处理 | 可关闭          |
| `info`    | 一般提示 (例: 数据同步完成, 新告警到达)             | 5s 自动消失    | 鼠标 hover 暂停 |

**样式规范**:

- **位置**: toast 居中顶部 (距顶部 16px, 水平居中, 多个 toast 纵向堆叠)
- **色彩**： 成功绿/错误红/警告黄/提示蓝/中性灰。图标、边框和文字同色彩，可轻微区别。
- **图标**: 每种类型配语义图标 (✓ / ✕ / ⚠ / ⓘ)
- **可访问性**: 文字内容可被屏幕阅读器读取; 错误 toast 强制 ARIA `role="alert"`

**联动接口**:

#### UI-FR-A180 功能降级

系统存在两种模式的功能降级：

- A类： 永久降级。当用户没有配置交易网关时为永久降级，直到用户配置后立即自动解除。
- B类： 临时降级。当系统配置了交易网关，但偶发不可连接。

> 对 A 类降级，状态记录在数据库中；对 B 类降级，状态记录在内存中，并在连接状态变更时更新。

对于 A 类功能降级：
- 实盘、仿真界面从 header 部分的导航按钮起 disable， 后台拦截所有相关路由，返回503
- 策略转仿真、回测按钮 disable
- 在被禁止入口，通过 mouse hover tip 提示： 此功能因交易网关未配置而无法使用。

```
+----------------------------------------+
| 股票代码: [________________________]   |
+----------------------------------------+
```

### UI-NFR-0050 局部刷新与失败隔离

| 有效需求 | 可测性 | 是否已决定 |
| -------- | ------ | ---------- |
| ✅        | ✅      | ✅          |

> **本 NFR 来源**: GPT-5.4 review §3.2 + Aaron Round 2 决策 Q2=A。

量化 UI 涉及资产/持仓/委托/告警/账户等多源数据, 任何单一数据源失败或局部刷新不得阻塞整页。具体约束:

- **失败隔离**: 单个数据区域 (例: 委托列表 / 账户信息 / 告警中心) 加载失败或刷新失败时, **不能**导致整页空白或报错。该失败区域独立展示"加载失败"占位与重试按钮, 其他区域保持正常。
- **不闪屏**: 局部刷新 (FastHTML `hx-swap` 等) 不得造成整页跳动或闪烁; 已渲染的内容不应被无谓重排。
- **占位重试**: 失败区域统一占位样式: 灰色背景 + 错误图标 + "加载失败"文字 + "重试"按钮; 点击重试后, 该区域独立重新加载, 不影响其他区域。

**参考实现**: `quantide/web/pages/trade_main.py` 的局部刷新与失败隔离模式。

**联动接口**:
- 上游: 所有 §2.x 含数据展示的 FR (例: §2.1 UI-FR-A160 / §2.3 UI-FR-0080 / §2.4 UI-FR-0390/410/411 / §2.5 UI-FR-0420/430 / §2.6 UI-FR-0310)
- 下游: 单元测试 + e2e 测试 (模拟局部失败, 验证其他区域不受影响)

### UI-NFR-0060 长任务交互

| 有效需求 | 可测性 | 是否已决定 |

| ✅        | ✅      | ✅          |

- **页面重入**: 用户关闭页面后再回到该任务页面, 能恢复到当前步骤 (例: 显示"已完成 X/Y, 正在做 Z"), 而不是回到任务入口。
