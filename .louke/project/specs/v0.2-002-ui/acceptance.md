## §2.1 系统壳层与认证

### UI-FR-A110 启动路由分流

- AC-1: 全新安装后访问 `/` 或任何非 wizard 路径 → 自动跳转到 init-wizard 第一步 (欢迎页), 此时访问 `/dashboard` 返回 403 或重定向到 wizard
- AC-2: 已完成 init-wizard 的系统, 未登录访问 `/` → 重定向到 `/login`; 登录成功后跳转回 `/`

### UI-FR-A120 单用户登录与会话

- AC-1: 登录页输入正确用户名+密码 → 跳转到 `/dashboard` 并建立会话; 后续访问受保护页面不再要求登录
- AC-2: 输入错误密码 5 次 → 仍可继续尝试 (不锁定账号); 连续错误不被记录到任何用户可见的登录历史

### UI-FR-A130 登出与个人设置

- AC-1: 用户菜单点击"退出登录" → 会话被清除, 跳转回 `/login`; 再次访问受保护页面要求重新登录
- AC-2: 用户菜单点击"修改密码" → 进入密码修改页, 需输入旧密码 + 两次新密码
- AC-3: 旧密码错误 → 提交失败, 表单显示"旧密码错误"; 旧密码正确但两次新密码不一致 → 表单显示"两次输入不一致"; 提交成功后用旧密码登录失败, 用新密码登录成功
- AC-4: 验证 UI **无** "改昵称" 入口 (story §1.2 Aaron "不做")

### UI-FR-A140 未登录访问重定向

- AC-1: 未登录访问 `/dashboard/accounts/123` → 重定向到 `/login?next=/dashboard/accounts/123`
- AC-2: 登录成功后 → 自动跳转到 `/dashboard/accounts/123` (deep link 保留); 浏览器返回按钮不破坏该行为

### UI-FR-A150 主界面布局

- AC-1: 登录后页面顶部 nav bar 包含 brand (左) + 导航菜单 (中) + 告警图标与未读数 + 用户菜单 (右); 左侧为多级侧边导航, 右侧为主内容区
- AC-2: 侧边栏折叠按钮 → 侧边栏收起, 主内容区扩展; 刷新页面后折叠状态被保留 (从 localStorage 读取)

### UI-FR-A160 告警中心入口与列表

- AC-1: 系统产生 3 条未读告警 (例如数据同步失败) → 顶部告警图标右上角显示红色小圆点 + 数字 "3"
- AC-2: 点击告警图标 → 进入告警中心列表, 列表按时间倒序, 每条展示时间 / 来源 / 级别 / 摘要
- AC-3: 点击单条告警"标记已读" → 该条样式变化 (灰色) + 顶部未读数减 1
- AC-4: 勾选多条点击"批量确认" → 选中条目状态变为"已确认", 顶部未读数相应减少
- AC-5 (Aaron Round 2 决策沉淀): 未读数刷新走**推送机制** (非定时轮询); 具体协议 (SSE / WebSocket) 由实施阶段决定; 验证: 关闭后端事件源 (例如停止推送服务), 未读数应在合理时间内反映变化 (而非依赖定时轮询)
- AC-6: 推送断线时, 告警图标显示"重连中"状态; 重新建立连接后, 未读数自动同步

### UI-FR-A170 UI 内通知 (toast / banner)

- AC-1: 提交订单成功 → 页面顶部居中弹出绿色 toast "已发送, 订单号 xxx" + ✓ 图标, 3 秒后自动消失 (鼠标 hover 时暂停)
- AC-2: 触发订单失败 → 弹出红色 toast "失败原因: ..." + ✕ 图标, **不自动消失**, 必须手动点击关闭
- AC-3: 跳过 wizard 某步骤 → 页面顶部紧贴 header 下方出现黄色 banner "已跳过 [步骤名], 可稍后处理" + ⚠ 图标, 持续到用户主动关闭
- AC-4: 多个 toast 同时触发 → 纵向堆叠显示, 不重叠; 每个独立计时
- AC-5: 错误 toast 含 ARIA `role="alert"` 属性, 可被屏幕阅读器读取

## §2.2 概览

> **概览 区块顺序** (Aaron Round 2 Q5=A 决策): D203 (告警分类, 顶部) → D201 (账户总览, 中部) → D202 (计划任务, 底部)。

### UI-FR-D203 告警分类显示 (概览 顶部)

- AC-1: 概览 **顶部**"告警"区块按"策略类 / 系统类"两组, 每组最多展示 5 条最新告警 (Aaron Round 2 Q5=A 决策: 从底部调整到顶部)
- AC-2: 每条告警按级别显示颜色: 错误 (红) / 警告 (黄) / 提示 (蓝)
- AC-3: 点击"策略类"分组标题 → 跳转到告警中心 (§2.1 UI-FR-A160) 并自动应用"策略类"过滤
- AC-4: 单条告警点击"标记已读" → 该条样式变化, 顶部未读数同步减少

### UI-FR-D201 账户总览 (概览 中部)

- AC-1: 登录后 `/dashboard` 页面中部"账户总览"区块显示 1 个实盘账户 (总资产/可用/持仓/当日盈亏/累计盈亏) + N 个虚拟账户列表 (按总资产降序); 虚拟账户列表的"基本指标"不区分 paper/live (统一展示总资产/可用/持仓/当日盈亏), paper/live 区分由 §2.4 UI-FR-0410 账户详情页提供 (Aaron Round 9 默认方案)
- AC-2: 点击虚拟账户行 → 跳转到该账户详情页 (§2.4 UI-FR-0410); 点击实盘账户区块 → 进入实盘交易界面 (§2.5 UI-FR-0420) (Aaron Round 9 默认方案: 支持点击进入策略详情)

### UI-FR-D202 数据/系统任务状态 (概览 底部)

- AC-1: 概览 底部"数据/系统任务状态"区块列出数据同步任务 (来自 §2.6 UI-FR-0310, 例: 日线行情/证券列表/交易日历/ST/涨跌停), 每条显示: 任务名 / 上次运行时间 (相对时间) / 状态 / 上次耗时
- AC-2: 失败任务置顶显示, 然后按上次运行时间倒序排列
- AC-3: 失败任务显示错误摘要 + "立即重试"按钮; 点击重试后, 任务被触发, 状态变更为"运行中"
- AC-4: 默认最多显示最近 10 条任务; 点击"查看全部" → 跳转 §2.6 UI-FR-0310 系统管理任务调度页
- AC-5: 验证 概览 底部**不包含**"今日计划运行"或"未来 N 天计划"区块 (策略为 runtime instance, 不由外部 cron 驱动, 见 spec UI-FR-D202 历史决策记录)

## §2.3 策略

### UI-FR-0010 策略发现与展示

- AC-1: 策略选择器列出所有 `is_builtin=False` (用户策略) 和 `is_builtin=True` (内置策略); 默认 `is_builtin=False` 优先 + `name` 字母升序
- AC-2: 用户策略与内置策略 `strategy_id` 冲突时, 列表只显示用户版本; 开启"显示被覆盖的内置策略"开关 → 内置版本出现并标注"被覆盖"
- AC-3: 搜索框输入 "ma" → 列表过滤为 `name` / `description` / `strategy_id` 含 "ma" 的策略
- AC-4: 按 `strategy_type` 多选过滤 (例如勾选 `day` + `live`) → 列表仅显示该类型策略

### UI-FR-0011 手动扫描策略更新

- AC-1: 策略选择器顶部"扫描更新"按钮 → 点击后按钮变为"扫描中"且不可点击
- AC-2: 扫描完成 → toast 提示"已加载 N 个新策略 / 更新了 M 个" (走 §2.1 UI-FR-A170) + 列表自动刷新
- AC-3: 扫描失败 → toast 红色提示, 按钮恢复可用, 列表保留扫描前状态

### UI-FR-0012 策略屏蔽与可见性

- AC-1: 策略详情页"屏蔽此策略"按钮 → 二次确认 → 该策略从 UI-FR-0010 选择器和 UI-FR-0091 回测报告列表中消失
- AC-2: "策略管理"页面 → "显示被屏蔽策略" 开关 → 开启后, 已屏蔽策略以灰色样式出现, 显示"取消屏蔽"按钮
- AC-3: 点击"取消屏蔽" → 该策略从"已屏蔽"列表移除, 重新出现在 UI-FR-0010 选择器

### UI-FR-0013 删除自定义策略

- AC-1: 策略详情页"删除此策略"按钮 → 弹出二次确认对话框, 显示策略名 + 输入框 (要求输入策略名)
- AC-2: 二次确认时显示明确提示"正在运行中 (实盘) 的策略不可删除"
- AC-3: 实盘中策略 → "删除此策略"按钮置灰 + tooltip "请先停止策略运行"
- AC-4: 仿真中策略 → 允许删除 (与实盘策略对比)
- AC-5: 删除成功 → 该策略及所有回测报告一并删除 (验证"联动删除"); 列表自动刷新
- AC-6: 删除失败 (例如策略名输入错误) → 表单显示"策略名不匹配", 按钮保持可点

### UI-FR-0020 运行时参数编辑

- AC-1: 启动回测表单包含字段: 本金 / 滑点 / 印花税比率 / 佣金比率 / 单笔最低佣金; 默认值按 spec 表格填充 (本金取上一次值, 滑点 0, 印花税 0.001, 佣金 0.0001, 单笔最低佣金 5)
- AC-2: 本金输入 `-100` → 提交被阻止, 显示 "本金必须 > 0"; 滑点输入 `0.2` → 提交被阻止, 显示 "滑点必须在 0~0.1"
- AC-3: 完成一次回测后, 启动仿真时表单显示"沿用上次 / 重新设置"两选项; 默认选中"沿用上次", 数值与上次一致
- AC-4: 修改运行时参数后启动回测 → 回测结果中"参数快照"显示本次参数; 后续启动仿真默认值与本次不同 (验证"不写入回测结果")

### UI-FR-0040 调度操作界面

- AC-1: 策略选择器选中某日线策略 → "启动回测"按钮可见; 选中后弹出表单含 策略参数 (可编辑) + 运行时参数 + 回测区间 (起止日期)
- AC-2: 已完成回测结果显示"转仿真"和"转实盘"两个按钮; 实时策略的回测结果不显示这两个按钮 (实时策略走 001-FR-240 直接进入仿真/实盘)
- AC-3: 仿真中策略显示"停止"按钮; 实盘中策略显示"停止"和"进入 dry-run"两个按钮
- AC-4: 点击"停止" → 策略状态变为"已停止", 已发出的订单继续在 001-FR-210 账本中执行 (验证"已发订单不撤回")

### UI-FR-0060 dry-run 切换与并行仿真视图

- AC-1: 实盘策略菜单点击"进入 dry-run" → 弹出二次确认对话框, 提示"已发订单仍会成交"; 确认后策略状态徽章变为 `dry-run`
- AC-2: 策略详情页"并行仿真视图"显示**单 Y 轴双线图**: 一条线为实盘/dry-run 期间真实净值, 另一条线为并行仿真模拟净值
- AC-3: dry-run 期间点击"退出 dry-run" → 二次确认; 确认后策略状态徽章恢复为 `live`

### UI-FR-0070 风控触发事件详情

- AC-1: 风控策略触发卖出后, "风控触发事件"页面列表展示每条事件的: 时间戳 / 标的 / 触发价 / 成本价 / 原因 / 超额收益
- AC-2: 超额收益列展示对应策略实例配置的 N 日窗口下的超额收益; N 日窗口未关闭时显示"计算中..."占位
- AC-3: "触发原因分布"饼图按 `reason` 字段分组; 点击某原因切片 → 触发事件列表过滤为该原因的事件
- AC-4 (Aaron Round 5 Q2, Round 6 应用 - 实例化时): 创建风控策略实例的表单中, 有 "超额收益窗口 (N 日)" 输入字段; 默认值 0; 范围 0~30 (含边界); 表单提交时校验; 校验通过后随策略实例一起持久化
- AC-5 (Aaron Round 5 Q2, Round 6 应用 - 实例化后只读): 风控策略实例详情页, "超额收益窗口 (N 日)" 字段显示为只读, 无修改入口 (无编辑按钮 / 无输入框)

## §2.4 账户
