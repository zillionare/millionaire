- `acceptance.md` UI-FR-460 AC-3: "某步下载失败 → 用户停留在该步, 显示错误详情 + '重试' / **'跳过'** 按钮; 跳过则该步骤标记为'待处理'"

**建议**: 修正 AC-3，区分两种场景：
- 下载失败：仅"重试"按钮，不提供"跳过"
- 通知配置：可"跳过"，标记为"待处理"

## 二、上游 FR 引用路径断裂（独立核实）

`spec.md` 中大量引用 `[001-FR-310]` / `[001-FR-320]` / `[001-FR-330]` / `[001-FR-340]` / `[001-FR-350]` / `[001-FR-220]` / `[001-FR-210]` / `[001-FR-013]` / `[001-FR-020]` / `[001-FR-125]` / `[001-FR-200]` / `[001-FR-230]` / `[001-FR-240]` / `[001-FR-250]` / `[001-FR-360]` / `[001-FR-380]` / `[001-FR-440]` / `[001-FR-450]`，链接目标均为 `../v0.2-001-strategy-framework/spec.md`。

**核实结果**:
- `../v0.2-001-strategy-framework/spec.md` 是个**索引文件**，不包含 FR 定义
- FR-310 / FR-320 / FR-330 / FR-340 / FR-350 / FR-220 / FR-210 等定义在 `spec-trading.md`
- FR-020 / FR-013 / FR-125 / FR-200 / FR-230 / FR-240 / FR-250 / FR-360 / FR-380 / FR-440 / FR-450 等定义在 `spec-strategy.md` 或 `spec-foundation.md`

**结论**: 所有指向 `spec.md#FR-XXX` 的链接都是断裂的，读者点击后看不到 FR 定义。

**建议**: 把 `spec.md` 中所有 `../v0.2-001-strategy-framework/spec.md` 链接改为指向具体子文档（`spec-trading.md` / `spec-strategy.md` / `spec-foundation.md`）。可在 `spec.md` 顶部增加一个"上游 FR 索引"小节，集中给出 FR 与子文档的映射，减少散落链接的维护成本。
